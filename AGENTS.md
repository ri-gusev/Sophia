# Инструкции Codex для Sophia

## Перед задачей

1. Прочитай этот файл и [текущее состояние](docs/development/CURRENT_STATE.md).
2. Прочитай релевантные документы по [карте документации](README.md#документация), обязательно проверь [инварианты](docs/architecture/INVARIANTS.md) и [решения](docs/architecture/DECISIONS.md).
3. Изучи реализацию затрагиваемых модулей, зависимости и конфигурацию. Отсутствие кода не означает разрешение создать приложение вне задачи.
4. Для нетривиальной задачи изложи краткий план изменений.

## Во время разработки

- Следуй принятой архитектуре; разделяй UI, бизнес-логику и доступ к данным.
- Соблюдай TypeScript strict mode; `any` допустим только с явным объяснением необходимости.
- Переиспользуй компоненты там, где это оправданно; избегай лишних абстракций.
- Обосновывай новые зависимости технической необходимостью.
- Не оставляй неиспользуемые импорты и мёртвый код.
- Соблюдай доступность и адаптивность; используй согласованные дизайн-правила.
- Явно обозначай демонстрационный контент и имитации; не выдавай фиктивные API за работающие функции.

## Запрещено

- Самовольно менять утверждённый стек и продуктовые требования.
- Переписывать рабочие модули без необходимости или удалять функциональность вне задачи.
- Добавлять микросервисы, Docker, Redis, очереди и другую инфраструктуру без необходимости.
- Хранить секреты в исходниках, коммитить `.env` или другие файлы с секретами.
- Отключать TypeScript или ESLint ради прохождения проверок.
- Подменять реализацию случайными заглушками без согласования.
- Выполнять разрушительные операции над Git-историей или пользовательскими данными.

## После задачи

1. Выполни доступные [проверки](docs/development/TESTING.md), исправь ошибки своих изменений.
2. Обнови `docs/development/CURRENT_STATE.md`, если состояние проекта изменилось.
3. При новых архитектурных решениях обнови соответствующие документы и журнал решений.
4. В ответе кратко опиши работу, перечисли изменённые файлы, результаты проверок и ограничения.

Не заявляй об успешной проверке, которая не запускалась. Подробные правила веди в профильных документах; здесь оставляй только рабочий порядок и ограничения.
