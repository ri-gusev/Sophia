# Правила UX

Правила применяются при реализации интерфейса. Визуальные значения определяет [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).

## Навигация и действия

- Подписи объясняют назначение ссылки или результат действия. Ссылки служат переходам, кнопки — действиям.
- Основной следующий шаг заметен; порядок навигации соответствует порядку чтения.
- Превью маршрута и атласа явно обозначаются как превью. Не показывать неработающий переход как доступную функцию.
- Недоступное действие объясняет причину; нельзя молча игнорировать нажатие.

## Обратная связь

- После ответа на демонстрационный вопрос показывать выбранный вариант и объяснение. Не сводить философское рассуждение к необъяснённому «верно/неверно».
- Различать выбор пользователя, результат и доступное следующее действие. Состояние передаётся текстом и семантикой, а не одним цветом.
- Загрузка показывается только при реальном ожидании; повторная отправка блокируется на время операции. Изменение размера блока не должно резко сдвигать содержимое.
- Ошибка объясняет, что произошло и как продолжить; введённые данные сохраняются, если это возможно. Технические детали и секреты не выводятся пользователю.
- Для пустого состояния указывать причину отсутствия данных и уместный следующий шаг. Не имитировать данные ради заполнения экрана.

## Доступность и адаптивность

- Использовать семантические заголовки, landmarks, подписи полей и доступные имена для кнопок с иконками.
- Все действия доступны клавиатурой; фокус видим, порядок предсказуем. Модальные элементы при появлении управляют фокусом и возвращают его инициатору.
- Динамическая обратная связь доступна экранному диктору, например через уместную live region; не перемещать фокус без необходимости.
- Проверять читаемость, контраст, увеличение текста и масштаб страницы, удобство нажатия на сенсорном экране.
- Не требовать hover для важных действий; избегать горизонтальной прокрутки основного содержимого на узких экранах.
- Уважать настройку уменьшения движения; смысл интерфейса сохраняется без анимации.

Практические сценарии проверки — в [TESTING.md](../development/TESTING.md).
