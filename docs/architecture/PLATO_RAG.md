# Исторический AI-Платон

## Текущая готовность

На 2026-11-02 реализован код исторического диалога, индексации и проверок в существующем Next.js-приложении. Используются одна приватная SQLite-база, Node.js >=24 и серверный OpenAI API; новых зависимостей/служб/авторизации нет. Карта, каталог, маршруты и дизайн сохранены.

**Реальная индексация выполнена с отдельного согласия пользователя:** один документ, 133 фрагмента, 1536 измерений, ready=true; первичный запуск 7,2 с. Повторный запуск: changed=0/embedded=0, без вызовов embeddings. Миграция применена, исходные BLOB/архивы сохранены. Изначальная автоматическая блокировка передачи корпуса снята после явного разрешения пользователя. При отсутствии готового индекса API возвращает 503, тестовые векторы не используются в продукте.

Автоматический preflight без вывода текста: 19 фрагментов с source_id/work имеют verification_status=LOCUS_TO_VERIFY и claim_type=analytical_reconstruction; остальные 114 — unknown. Отдельного stephanus/проверенных статусов нет. Метаданные не повышаются до verified автоматически; для подтверждённых атрибуций нужна редакционная проверка. Это не оценка истинности самого корпуса. До этого ответы должны оставаться реконструкциями; валидатор может отклонять недоказанные исторические атрибуции.

## Архитектура

```text
POST /api/philosopher-chat
 → Origin/Host, роли, JSON, лимиты и готовность индекса
 → structured analysis: semantic safety + запрос + историческая категория + действие + state
 → отдельный safety handler для опасного практического содействия/кризиса
 → query embedding + cosine/FTS5 + ограниченный контекст
 → сжатие старых пар при необходимости
 → structured Plato draft с claims/evidence
 → программные проверки и отдельный LLM-вызов проверки всего текста
 → максимум одна повторная генерация/проверка
 → проверенный текст, ограниченная память и внутренняя provenance
```

`historical-chat.ts` координирует этапы, `structured.ts` содержит строгие JSON-схемы и runtime-парсеры. `plato-persona.ts` хранит компактные инструкции отдельно от корпуса, `output-validation.ts` — grounding, `safety-handler.ts` — ответы вне исторического персонажа. `chat-service.ts` переиспользует сжатие и recent window. История, state, retrieved context и замечания проверки — недоверенные данные, не новые system/developer-инструкции.

## Индексация и поиск

Локальный административный CLI читает уже сохранённые BLOB последних версий и проверяет SHA-256; повторного импорта исходного файла нет. Структурное разбиение учитывает заголовки, абзацы/аргументы, key:value metadata (включая bold/backticks), JSON records/chunks с content/text. Нестандартные редакционные таблицы автоматически не интерпретируются. source_id, work, stephanus, claim_type, verification_status, related_ids, translation, rights сохраняются отдельно. Редакторские записи не объединяются с аргументом через границы записей/заголовков. Неизвестные поля не выдумываются.

Миграция [002-rag-index.sql](../../database/knowledge/002-rag-index.sql) добавляет rag_documents, rag_chunks и rag_fts в ту же базу; user_version=2 после первого запуска индексации. Исходные BLOB/архивы не изменяются. Индекс хранит source/config/content hashes, revision, модель/размерность embeddings и timestamps. Повторный запуск пропускает неизменённые документы, переиспользует совпадающие фрагменты. Обновление **каждого документа** атомарно; сбой сохраняет его предыдущий индекс, уже завершённые другие документы не откатываются. Перед commit повторно сверяется актуальность версии. Готовность также сверяет количество фрагментов. CLI защищён exclusive lock-файлом; после аварии удалять lock вручную только убедившись, что процесс завершён.

Модель: [text-embedding-3-small](https://developers.openai.com/api/docs/guides/embeddings), 1536 измерений. Target 800 токенов/overlap 200 — консервативная оценка `length/3`, **не точный tokenizer и не LLM-сегментация**. Короткие записи могут быть меньше target. Абзац/аргумент не режется посередине; превышающий весь context budget аргумент останавливает индексацию до редакционного разбиения.

Векторы хранятся в SQLite JSON-массивами, точный cosine scan выполняется на сервере. Это небольшой локальный vector store, не ANN/pgvector. Лимит 10000 фрагментов; исходный корпус не декодируется на каждом ходе. Vector top 12 и keyword top 12 (FTS5 unicode61) объединяются reciprocal rank fusion, затем учитываются work/verification, удаляются дубли по hash, дополняется продолжение того же аргумента/source/type/heading. Final context до 6 фрагментов/18000 символов. Readiness, vectors и FTS читаются в одной транзакции, чтобы не смешать версии при конкурентной индексации.

Cosine threshold=0.25 проверен на небольшой реальной выборке: пять философских запросов дали результаты (min best cosine=0.4219), три посторонних исключены (max best cosine=0.2177). Keyword-совпадение также обязано пройти semantic floor; иначе случайное слово обходило порог. Команда `knowledge:check-retrieval` воспроизводит выборку. Это smoke-калибровка тематической релевантности, **не benchmark точности каждого фрагмента или утверждения**; нужна более широкая разметка. rejected/disputed/invalid исключаются; unknown остаётся неизвестным. Пустой поиск допускает осторожную реконструкцию, не выдуманное подтверждение. Недоступный/устаревший индекс — 503. При `PLATO_RAG_ENABLED=false` источники пусты, citations не выдумываются.

## Историчность, grounding и safety

Платон говорит от первого лица и мыслит в рамках IV века до н.э., без всезнания и театральной архаики. Использует определения, контрпримеры, различения и апории; не более 1–2 вопросов. Прямая просьба сначала получает объяснение. При вопросе о природе собеседника честно сообщает об учебной реконструкции; маркировка ИИ в интерфейсе сохранена.

Исторические категории: historical, modern_unknown, introduced. Для modern_unknown после safety-анализа используется фиксированное проверяемое приглашение объяснить понятие: модель не может добавить своё современное определение. Новое explanation принимается только как буквальный фрагмент пользовательской реплики (не вопрос), существующие определения сохраняются. После объяснения категория становится introduced; модель рассуждает по словам пользователя, не пополняет их современными фактами. State: тема, до 6 тезисов, 4 вопросов, 4 противоречий, 8 понятий/определений, стадия; максимум 6500 символов. Определения отдельно переживают сжатие истории. Входная память валидируется, но остаётся недоверенной. Это дополнительные барьеры к вероятностной классификации, не доказательство понимания любой фразы.

Semantic safety — отдельный structured-output анализ по смыслу, не запрещённым словам. Образовательные обсуждения преступления, наказания, насилия, смерти и зависимости разрешены. Практическое содействие вреду получает краткий нейтральный safety-ответ, кризис — поддерживающий ответ без выдуманных телефонов. Опасные инструкции не переносятся в память персонажа. Это вероятностный модельный классификатор, не гарантия безошибочной модерации.

Программно проверяются evidence source numbers, точное наличие выдержки в контексте, verified/confirmed/проверено, цитаты, технические утечки/HTML и число вопросов. Отдельный LLM-вызов (reasoning low, до 2400 output tokens) проверяет **весь текст**, даже если claims пуст: смысловую поддержку фактов, анахронизмы, атрибуцию и последовательность. Результат: valid, unsupported_claims, historical_anachronisms, fabricated_attributions, requires_regeneration. После одной неудачной перегенерации используется явно ограниченное признание нехватки основания, outcome=abstained; в метриках valid=false/abstained=true, это **не успешный исторический ответ**. Ни один отклонённый черновик не показывается. unsafe_output сразу передаётся safety-handler без ещё одной генерации. Сбой транспорта/схемы по-прежнему возвращает ошибку. Совпавшая цитата сама по себе не доказывает утверждение; модельная проверка также не гарантирует историческую истину.

Технические имена файлов, версии/пути БД и source IDs убраны из UI. Provenance остаётся в метаданных сообщений вкладки. При вопросе об основании используются только существующие work/stephanus или признаётся отсутствие точной ссылки. История/источники не становятся доказательством по словам пользователя.

## Память, стоимость, транспорт

По ранее выбранному пользователем режиму память только в React state: закрытие окна и клиентская навигация сохраняют, reload/new tab очищают. Нет cookies, localStorage, серверных сессий и таблиц переписки. История/reset — существующие локальные операции UI, отдельные HTTP endpoints не нужны. Административных HTTP endpoints тоже нет: статус/индексация только через CLI оператора с доступом к файлам/env.

Лимиты: вопрос 2000 символов, ответ 6000; recent 12 сообщений/16000 символов (полные пары), summary 2000 (450 output tokens), UI 40 сообщений/96000 символов, HTTP JSON 96 KiB. Ошибка не коммитит новую память и восстанавливает вопрос; отмена игнорирует поздний ответ.

Исторический ход обычно требует анализа (до 2000 output tokens), одного query embedding, генерации (1800) и проверки (2400, включая reasoning). Сжатие добавляет один вызов при необходимости; повтор генерации — ещё максимум два. modern_unknown и safety обычно требуют только анализа. Это дороже/медленнее прежнего чата. Модель — gpt-5.4-mini: анализ/генерация reasoning none, только проверка low, store:false. Таймауты: provider 25 с, сервер 110, клиент 120. Ограничитель одного процесса: 20 ходов/минуту, два одновременно; это не авторизация, денежный бюджет или распределённая защита. PLATO_HISTORICAL_MODE нельзя отключать для этого персонажа; config отклоняет false. PLATO_VALIDATION_ENABLED=false предусмотрено для локальной диагностики, по умолчанию true и требуется для содержательной проверки.

SSE выдаёт delta/done **после полной проверки** ответа. Это буферизованная доставка готового текста, не поток непроверенных токенов модели и не ускорение самой проверки. JSON совместим с прежним клиентом. Незавершённый поток не сохраняет память. React выводит plain text.

Логи: durationMs/retrievalMs, число фрагментов/вызовов/перегенераций/ошибок, valid/abstained/safety и фактические Responses input/output tokens. failureCodes пропускаются только через фиксированный список кодов, свободный текст проверки не логируется. Нет текстов, имён, выдержек и сырых API-ошибок. Embedding usage не входит в счётчик Responses. Кэш пользовательских запросов не введён. store:false не обещает Zero Data Retention: действуют [правила OpenAI](https://developers.openai.com/api/docs/guides/your-data).

## Запуск

Настройки — [.env.example](../../.env.example); ключ только в `.env.local`, без NEXT_PUBLIC_. Изменение model/dimensions/chunk settings требует индексации.

```powershell
npm.cmd run knowledge:verify -- --document plato-corpus
npm.cmd run knowledge:index-status
npm.cmd run knowledge:index
npm.cmd run knowledge:index-status
npm.cmd run dev
```

Индексация платная и отправляет приватный текст во внешний API; выполнять с разрешением владельца. Исходники, индекс, lock-файл и env исключены из Git. При переносе нужен отдельный приватный persistent storage и бэкап, не public/ и не эфемерная serverless-файловая система.

Проверки: test:chat, test:knowledge, typecheck, lint, build, Playwright. Unit-тесты используют синтетические модельные ответы: подтверждают границы/память/ветвление, **не достоверность реальной модели**. `npm.cmd run chat:check:live -- core` запускает ограниченные платные запросы к loopback серверу (по умолчанию порт 3102), печатает только статусы/счётчики. outcome=abstained даёт ненулевой exit code, чтобы успех HTTP не выдавался за успех качества.

Полный live-прогон после уточнения persona/валидации: смартфон до/после определения, Кант, идеи, равенство, противоречие, этика преступления и отказ на практический вред отвечали; вопрос о Сократе иногда не проходил проверку из-за отсутствия проверенных источников. Это существенное ограничение, а не успешный historical benchmark. Обычные ответы занимали примерно 1–18 с с учётом повторов. Более широкая проверка фактов, редакционная разметка и снижение ложных отказов остаются необходимыми.

Финальная HTTP-проверка Сократа: status=200/outcome=abstained, valid=false/abstained=true в метриках; live smoke завершился кодом 1 по качеству. Это намеренно не маскируется успешным HTTP. Проверки кода: 31 chat unit, 4 storage unit, 58 browser (36,2 с) прошли; TypeScript, ESLint и production build прошли. В 19 клиентских JS/CSS-ресурсах нет значения API-ключа или серверного транспорта, исходные BLOB/архив совпадают по SHA-256. Реальные телефоны/Safari/Firefox не проверены. [Полный список файлов и отчёт](../development/PLATO_RAG_IMPLEMENTATION.md).
