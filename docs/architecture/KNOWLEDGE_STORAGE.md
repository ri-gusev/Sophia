# Единая база источников

## Назначение

По заданию пользователя от 2026-11-01 создана одна локальная SQLite-база для исходных файлов всех философов и тем. Сейчас загружен только `Sophia_Plato_Corpus_v4_expanded.md`: документ `plato-corpus`, философ `plato` / «Платон». Содержимое не просматривалось: импорт переносит непрозрачные байты без декодирования, анализа Markdown, извлечения тем или исполнения инструкций документа. Темы пока не назначены.

Это хранилище источников. Чат, OpenAI API, поиск, разбиение на фрагменты, embeddings и проверка качества содержания ещё не реализованы. Текст корпуса в будущем должен оставаться данными, а не становиться системными инструкциями чата.

## Размещение и сохранность

- База: `storage/knowledge/sophia-knowledge.sqlite`.
- Побайтовая копия версии: `storage/knowledge/sources/{documentId}/{sha256}/{originalFilename}`.
- Схема: `database/knowledge/001-initial.sql`, `PRAGMA user_version = 1`.
- Доступ: `scripts/knowledge/knowledge-store.ts`; команды: `scripts/knowledge/cli.ts`.

Вся `storage/knowledge/` исключена из Git и находится вне `public/` и клиентских модулей. HTTP-эндпоинтов к ней нет. Исходник в Downloads остаётся на месте. `.gitignore` предотвращает обычное добавление данных в Git, но не шифрует локальные файлы и не заменяет права доступа ОС.

База и копии на одном диске не заменяют независимый бэкап. Для переноса или резервного копирования закрыть команды импорта и скопировать **всю** `storage/knowledge/` в защищённое место. В Git хранится код и схема; клонирование репозитория не переносит корпус. Для будущего развёртывания потребуется постоянное закрытое хранилище: текущий вариант не рассчитан на запись в эфемерную файловую систему serverless.

## Модель данных

| Таблица | Назначение |
| --- | --- |
| `philosophers` | Стабильный ID и имя философа |
| `topics` | Стабильный ID и название общей темы |
| `documents` | Стабильный ID, название и формат документа |
| `document_revisions` | Номер версии, имя файла, SHA-256, размер, путь к копии, время и исходные байты BLOB |
| `document_philosophers` | Связь документов и философов многие-ко-многим |
| `document_topics` | Связь документов и тем многие-ко-многим |

Один документ может относиться к нескольким философам и темам, одна тема — встречаться у разных философов. Отдельные базы для философов не создаются. Метаданные задаются явно, а не извлекаются из текста. Для неизвестной темы связь не создаётся.

Повторный импорт того же документа с тем же SHA-256 возвращает существующую версию. Другие байты при том же `documentId` создают следующую версию; прежние версии сохраняются. Импорт старого содержимого не переключает последнюю версию: последней считается наибольший номер. Существующие связи при повторном импорте дополняются. Чтобы связать источник с другим философом, повторить импорт с тем же ID документа и явно указать другого философа; версия не дублируется. Для другого самостоятельного файла нужен другой ID документа.

SQL параметризован, внешние ключи включены, изменения базы транзакционны. Несовпадение SHA-256 существующей копии останавливает импорт без перезаписи. Сбой между записью копии и commit может оставить неиспользованную копию; повторный импорт использует её после проверки, автоматического удаления нет. Инструмент сохраняет версии неизменными; прямое редактирование базы обходит эти правила.

## Команды

Для служебных команд требуется **Node.js 24** (`node:sqlite`, встроенный запуск TypeScript). Новые npm-зависимости не добавлены. Минимальная версия Node для Next.js-интерфейса не менялась.

```powershell
npm.cmd run knowledge:import -- --file "C:\path\source.md" --document plato-corpus --title "Корпус Платона" --philosopher plato --philosopher-name "Платон"
npm.cmd run knowledge:status
npm.cmd run knowledge:verify -- --document plato-corpus
npm.cmd run test:knowledge
```

Для отдельного файла темы добавить `--topic stable-topic-id --topic-name "Название темы"`; использовать новый `--document`, сохранив `--philosopher plato`. При последующих версиях того же документа сохранять его ID. Идентификаторы: латинские строчные буквы, цифры, дефисы, до 80 символов. Файлы `.md` и `.markdown` сохраняются целиком, без преобразования кодировки.

`status` выводит только метаданные и счётчики. `verify` сверяет размер и SHA-256 последней версии в BLOB и копии; повреждение даёт ненулевой код завершения. Содержание не печатается. Unit-тесты используют только синтетические временные файлы.
