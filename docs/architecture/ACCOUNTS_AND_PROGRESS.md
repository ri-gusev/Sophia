# Аккаунты и учебный прогресс

Next.js App Router обслуживает формы и HTTP API. Серверный модуль аккаунтов использует встроенные `node:crypto` и `node:sqlite`. SQLite соответствует одноузловому развёртыванию Sophia и позволяет выполнить активацию, отзыв сессий и слияние прогресса транзакционно. Дополнительный runtime-пакет не нужен. Встроенный Argon2id доступен в Node.js начиная с 24.7.0. Better Auth был рассмотрен, но его стандартная схема хранит исходный session token в столбце `token`. Для соблюдения требования о хешировании пришлось бы заменять этот механизм. [Node.js Crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html#cryptoargon2algorithm-parameters-callback) · [Better Auth Session Management](https://better-auth.com/docs/concepts/session-management).

## База

Отдельный файл аккаунтов имеет собственные `application_id` и `user_version`. Миграции 1 и 2 выполняются в SQLite-транзакции. Учётные записи, корпус и финансовый журнал чата используют разные файлы. Связи с пользователем защищены внешними ключами.

| Таблица | Содержание |
| --- | --- |
| `account_users` | UUID, уникальный нормализованный email, имя, хеш пароля, даты подтверждения email, регистрации и изменения |
| `account_sessions` | SHA-256 токена сессии, UUID пользователя, создание и срок действия |
| `account_challenges` | SHA-256 одноразового токена, назначение, адрес, связанные данные и срок действия |
| `account_rate_limits` | Окна ограничений запросов по операции, сети, адресу или глобальному счётчику |
| `account_entitlements` | Пара `user_id` и разрешение, дата выдачи. Сейчас используется `ai_chat` |
| `account_lesson_progress` | Отметки завершения, прежнего завершения и слайд возобновления по паре пользователь и урок |
| `account_slide_progress` | Уникальное подтверждение по тройке пользователь, урок и слайд |
| `account_last_opened_lesson` | Последний открытый урок пользователя со ссылкой на его запись прогресса |

## Регистрация и восстановление

`/register` валидирует имя, адрес и пароль. Поля регистрации, нового пароля и изменения имени ограничены 50 символами. Новый пароль требует минимум 8 символов. Вход и запрос восстановления принимают данные ранее созданных аккаунтов с прежними ограничениями. Email нормализуется в одну форму для входа и уникальности. По одноразовой ссылке владелец почты устанавливает пароль и активирует аккаунт. Это защищает от захвата аккаунта через пароль, который мог указать другой посетитель в первой форме. После активации пользователь входит через `/login`.

Единый список разрешённых доменов в `src/features/account/account-contract.ts` используют форма, сервер и пользовательское соглашение `/terms`. При регистрации и повторной отправке сервер проверяет домен до записи заявки и обращения к почтовому транспорту. Сравнение точное, без учёта регистра ASCII и внешних пробелов адреса. При активации сервер сверяет сохранённый адрес заявки, включая ссылки, выданные до введения ограничения. Вход и сброс пароля для активированных аккаунтов используют действующий адрес независимо от его домена. Профиль позволяет менять имя. API профиля отклоняет поле `email`. При добавлении смены адреса новый email должен пройти эту же проверку на форме и на сервере до записи заявки и отправки письма, а запись аккаунта может измениться после подтверждения нового адреса. [Источники по доменам и аудит передач](../audits/CROSS_BORDER_DATA_TRANSFERS.md).

Подтверждение действует 24 часа. Через `/forgot-password` можно запросить ссылку сброса на 30 минут. Ответ формы восстановления одинаков для существующего и неизвестного адреса. Токены формируются из 32 случайных байт, передаются во фрагменте URL и используются явно при отправке формы. Одноразовая запись погашается в транзакции. Сброс пароля отзывает все сессии. Пароль хранится как Argon2id с 16-байтной солью, 32-байтным хешем, памятью 64 МиБ и тремя проходами. Одновременные вычисления ограничены.

Вход выдаёт новый случайный токен, а база хранит его SHA-256. Срок сессии составляет 30 дней с момента выдачи. Выход удаляет запись. Cookie имеет `HttpOnly`, `SameSite=Lax`, `Path=/`, а в публичном режиме также `Secure` и префикс `__Host-`. Запись разрешена только с доверенного Origin. Account API проверяет доверенный прокси, ограничивает JSON 8 КиБ и ограничивает чтение тела пятью секундами. Лимиты частоты постоянны при перезапуске.

Первая и повторная отправки письма подтверждения используют общий лимит регистрации. Это до 12 запросов на сеть, 3 на адрес и 60 суммарно за час, с общим пределом 240 в сутки. Повторная отправка доступна, пока есть действующая заявка. Вход ограничен 35 попытками на сеть, 6 на адрес и 300 суммарно за 15 минут. Кодовые операции и восстановление имеют собственные окна. Параллельное хеширование ограничено двумя операциями на процесс.

## Данные обучения

Гости используют прежнее локальное хранилище. Для зарегистрированных серверная сессия определяет владельца каждой операции. Идентификатор, который UI отправляет для проверки смены аккаунта, только отклоняет устаревший запрос. Навигация и кэш относятся к конкретной учётной записи. Смена аккаунта и сброс пароля уведомляют другие вкладки. При сбое базы во время определения действующей сессии карта и Атлас остаются доступны, а запуск урока предлагает повторить загрузку. Это сохраняет гостевые записи изолированными.

Сервер хранит зачёт слайда, подтверждение финала, позиции возобновления в уроках и последний открытый урок. Подтверждения объединяются, а завершение требует зачёта слайдов. Для мест возобновления действует порядок принятых сервером открытий. Параллельные записи подтверждений не затирают друг друга. Тексты ответов, этапы упражнений и прокрутка остаются локальными и изолированы по аккаунту. Их можно продолжить на том же устройстве.

В профиле можно явно перенести гостевой прогресс. Рассматриваются только известные уроки, ограниченные структуры и проверенные ID из ключей `sophia.lesson-completions.v1`, `sophia.lesson-progress.v2:*` и `sophia.lesson-resume.v1:*` / `v2:*`. Перенос сохраняет гостевые данные на устройстве, объединяет зачёты, сохраняет существующие позиции аккаунта и допускает повтор. Прежняя отметка завершения остаётся отдельно от подтверждения всех слайдов. Учебные данные из браузера можно изменить вручную. Они не выдаются за сертификат и не используются для прав доступа или выплат.
