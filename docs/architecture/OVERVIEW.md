# Обзор архитектуры

## Фактическое состояние

Реализовано единое Next.js-приложение App Router. `src/app/(marketing)/page.tsx` — серверная композиция трёх секций `/`; `src/app/(learning)/learn/page.tsx` — серверная композиция карты курса `/learn`. У групп независимые layouts, а шрифт и CSS подключены в общем корневом layout. Клиентские границы: `Header` (мобильное меню), `PhilosophyQuestion` (выбор и повтор), `Reveal` (Motion) и `CourseMap` (навигация по карте и диалог темы). Хранилище, API, авторизация и серверные операции отсутствуют.

## Публичная и учебная части

Публичная страница собирает Hero, маршрут и выбор направления. Данные маршрута и направления находятся в `src/content/landing.ts`. Самостоятельный вопрос о корабле Тесея вместе с данными расположен в `src/features/philosophy-question/`. У него нет правильного ответа: любой выбор раскрывает одно объяснение. Выбор хранится только в React state и сбрасывается при повторе или перезагрузке; учебный движок не создаётся.

`/learn` содержит заголовок курса, возврат и горизонтальную карту пяти эпох с 25 круглыми шагами. `src/features/course-map/` объединяет клиентское управление картой, отдельные типизированные данные эпох/шагов и локальные стили. Мир 3800 × 650 px состоит из пяти сцен эпох шириной 760 px и четырёх отредактированных переходов из `public/images/course-map/`. Переходы закрывают границы сцен и смягчаются CSS-маской по внешним краям. Один SVG-путь и объёмные DOM/CSS-кнопки размещаются поверх фона. Карта не использует картографический движок, canvas, внешний API или дополнительную зависимость.

Внутреннее состояние карты нужно только для текущей эпохи, перемещения и выбранной ознакомительной темы. Нативный `<dialog>` показывает описание темы и статус недоступного полного урока; прохождение, XP и завершённость не имитируются. Данные не записываются в браузерное или серверное хранилище. Уменьшение движения отключает плавные перемещения. Геометрия пути хранится вместе с типизированными данными отдельно от TSX.

Компактная шапка даёт переход на главную через логотип и к третьей секции через `/#how-it-works`. Межстраничные переходы и ссылки навигации используют `next/link`; route groups не меняют публичные URL. Основание развития `/learn` после Phase 2 — ADR-005, восстановление масштаба и выбранных сцен — ADR-006 в [DECISIONS.md](DECISIONS.md).

```text
Страница App Router → UI-компоненты → логика взаимодействия
                          ↑                 ↑
                     типизированный учебный контент
```

Server Components отдают статические секции; клиентские компоненты ограничены взаимодействиями. `Reveal` принимает серверное содержимое через `children`, не переносит всю страницу в клиентский модуль и не скрывает текст до гидратации. `src/components/ui/button.tsx` использует композицию shadcn/ui с Radix Slot для семантических ссылок. Цвета, размеры и состояния централизованы в `src/app/globals.css`.

## Будущие границы

Когда отдельная задача потребует хранения, UI будет обращаться к серверной границе, сервер — к бизнес-логике и слою доступа к данным. UI не обращается к БД напрямую. Проверка прав и значимых изменений выполняется на сервере. Сейчас эти слои не создаются: хранение, аккаунты и платежи исключены из первого этапа.

Размещение модулей описывает [STRUCTURE.md](STRUCTURE.md), ограничения — [INVARIANTS.md](INVARIANTS.md), основание выбранного направления — [DECISIONS.md](DECISIONS.md).
