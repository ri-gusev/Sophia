# Обзор архитектуры

Текущий чат расширен историческим pipeline с отдельными semantic analysis/safety, структурированным state, индексом SQLite cosine/FTS и проверкой ответа до доставки. Статус реальной индексации, схема и ограничения — [PLATO_RAG.md](PLATO_RAG.md), ADR-013. Описание прежнего лексического этапа ниже историческое.

## Фактическое состояние

Реализовано единое Next.js-приложение App Router. `src/app/(marketing)/page.tsx` — серверная композиция трёх секций `/`; `src/app/(learning)/learn/page.tsx` — серверная композиция карты курса `/learn`. У групп независимые layouts, шрифт и CSS подключены корневым layout. Клиентские границы: Header, PhilosophyQuestion, Reveal, CourseMap и интерфейс разговора с PlatoChatProvider. Один серверный API-маршрут `/api/philosopher-chat` обслуживает Платона, читает общую базу источников и обращается к OpenAI. Авторизация и серверное сохранение переписки отсутствуют.

## Публичная и учебная части

Публичная страница собирает Hero, маршрут и выбор направления. Данные маршрута и направления находятся в `src/content/landing.ts`. Самостоятельный вопрос о корабле Тесея вместе с данными расположен в `src/features/philosophy-question/`. У него нет правильного ответа: любой выбор раскрывает одно объяснение. Выбор хранится только в React state и сбрасывается при повторе или перезагрузке; учебный движок не создаётся.

`/learn` содержит заголовок курса, возврат и горизонтальную карту пяти эпох с 24 основными узлами и одной дополнительной веткой Платона. `src/features/course-map/` объединяет клиентское управление картой, отдельные типизированные данные эпох/шагов и локальные стили. Мир 5900 × 650 px состоит из пяти независимых сцен по 1180 px и четырёх нарисованных переходов по 400 px из `public/images/course-map/adventure/`. Их положение и DOM-кнопки используют одну систему координат. Основная тропа входит в иллюстрации; SVG используется только для короткой дополнительной ветки. Общая ширина вычисляется по количеству эпох. Ресурсы и соседние переходы выбираются по ID эпох, поэтому расширение не требует единой гигантской панорамы. Карта не использует картографический движок, canvas, внешний API или дополнительную зависимость.

Внутреннее состояние карты нужно только для текущей эпохи, перемещения и выбранной ознакомительной темы. Нативный `<dialog>` показывает описание темы и статус недоступного полного урока; прохождение, XP и завершённость не имитируются. Данные не записываются в браузерное или серверное хранилище. Уменьшение движения отключает плавные перемещения. Учебные описания остаются в `course-map-data.ts`. Отдельная конфигурация `course-map-config.ts` задаёт устойчивые ID, типы main/branch, eraId, позиции, иконки, действия и parentId. Действия и геометрия узлов не зависят от индекса в массиве.

Античность содержит Досократиков, Платона, Аристотеля и Стоицизм; ветка «Последователи Платона» связана с ID plato. Нажатие на Платона открывает `PhilosopherCatalog` с данными из `philosopher-catalog-data.ts`. На экране от 1000 px это отдельная правая колонка с немодальной семантикой диалога, карта остаётся в левой половине. На меньших экранах используется полноэкранный нативный модальный диалог. При закрытии восстанавливаются прокрутка карты, позиция страницы и фокус. Каталог содержит описание, статус и три раздела. Основные темы — типизированный массив lessons со стабильными ID и семью названиями из изображения пользователя; разделы произведений и дополнительных материалов остаются пустыми. Секции различаются по kind (lessons/placeholder). Счётчик и нумерация выводятся из данных; расширение списка не требует правок JSX. Первой теме явно назначен contentId plato-introduction. Нажатие показывает LessonIntroduction под всей областью карты/каталога на том же URL и прокручивает страницу к нему, переводя фокус на заголовок. Desktop-каталог остаётся рядом с картой; mobile-dialog закрывается перед прокруткой. Остальные темы отключены с пометкой «Скоро».

В src/features/course-lesson/ текст, вопрос и варианты вынесены в lesson-data.ts; компонент содержит только локальный выбор одного radio-ответа. Это один вводный экран, без оценки правильности, продолжения, сохранения или нового учебного движка. Легенда из текста пользователя не превращается в подтверждённую биографию, варианты вопроса не выдаются за цитаты.

Компактная шапка даёт переход на главную через логотип и к третьей секции через `/#how-it-works`. Межстраничные переходы и ссылки навигации используют `next/link`; route groups не меняют публичные URL. Основание развития `/learn` после Phase 2 — ADR-005, восстановление масштаба и выбранных сцен — ADR-006, переход к единому 2D-ландшафту — ADR-007, детальные сцены — ADR-008, узлы Античности и каталог Платона — ADR-009 в [DECISIONS.md](DECISIONS.md).

```text
Страница App Router → UI-компоненты → логика взаимодействия
                          ↑                 ↑
                     типизированный учебный контент
```

Server Components отдают статические секции; клиентские компоненты ограничены взаимодействиями. `Reveal` принимает серверное содержимое через `children`, не переносит всю страницу в клиентский модуль и не скрывает текст до гидратации. `src/components/ui/button.tsx` использует композицию shadcn/ui с Radix Slot для семантических ссылок. Цвета, размеры и состояния централизованы в `src/app/globals.css`.

## Атлас `/atlas`

Серверная страница импортирует `AtlasView`, клиентскую оболочку в `src/features/philosophy-atlas/`. Она загружает `EarthGlobe` через `next/dynamic` с `ssr:false`; Three.js/Fiber/Drei не рендерятся на сервере и не загружаются сценой на других страницах. Оболочка содержит UI, статусы загрузки/ошибок, повтор, клавиатуру и команды камеры. `AtlasControls` владеет OrbitControls, ограничениями дистанции 1.35–12 при радиусе Земли 1 и fit по меньшему углу обзора. При resize сохраняются направление и достаточная дистанция камеры; только при необходимости дистанция увеличивается. Явный сброс возвращает исходный вид, состояние камеры нигде не сохраняется.

Сцена использует demand-render, DPR до 2 (fallback 1.5), сферу 128 × 96 сегментов, `MeshStandardMaterial`, ACES tone mapping, нейтральное фоновое заполнение 1.8 и направленный солнечный свет 1.5 при exposure 1.05. `earth-palette.ts` согласует всю поверхность с пастельным UI: приглушает насыщенность и светлые тона суши, поднимает тени лесов, смягчает серо-голубой океан и контраст батиметрии. Коррекция выполняется до освещения без дополнительных texture samples, размытия или sharpening; JPEG не изменены. Локальная sRGB-текстура 8192 × 4096 выбирается по maxTextureSize, coarse pointer и доступной подсказке памяти; иначе используется 4096 × 2048. Trilinear mipmaps, repeat по долготе/clamp на полюсах, ограниченная GPU анизотропия. При отказе загрузки/декодирования/выделения GPU-памяти для 8K используется 4K. Качество передаётся в Canvas декларативно, чтобы DPR не сбрасывался при обновлениях. Текстура загружается без глобального loader-кеша, явно освобождается при размонтировании/ошибке/повторе; запоздавший callback игнорируется. Fiber освобождает геометрию/материал, Drei — обработчики controls. Потеря WebGL-контекста переводит UI в состояние ошибки с повторным созданием сцены. Нет API атласа, БД, маркеров, географических подписей или изменений карты курса. Источник, бюджет памяти и экспорт учтены в [README текстур](../../public/textures/earth/README.md), решение — ADR-015.

## Границы остальных модулей

`src/features/philosopher-conversation/` содержит общий интерфейс разговора на двух страницах; React portal открывает нативный dialog в document.body. Корневой PlatoChatProvider сохраняет ограниченную память в React state при клиентской навигации, сбрасывая её после reload. Общие контракты отделены от server-модулей HTTP, прикладной логики, поиска и OpenAI. Модель получает небольшое окно истории, резюме и выдержки, а не весь корпус. Ключ читается только сервером из `.env.local`. Подробнее — [PHILOSOPHER_CHAT.md](PHILOSOPHER_CHAT.md), ADR-012.

Когда отдельная задача потребует подключения хранения к приложению, UI будет обращаться к серверной границе, сервер — к бизнес-логике и слою доступа к данным. UI не обращается к БД напрямую. Проверка прав и значимых изменений выполняется на сервере. Аккаунты и платежи пока не реализуются.

По отдельному заданию создана единая локальная база корпусов: CLI → KnowledgeStore → SQLite и побайтовые копии источников. Связи многие-ко-многим позволяют относить документ к нескольким философам и темам. База находится вне публичных ресурсов, не импортируется клиентом, не связана с уроками или сохранением прогресса. Подробности — [KNOWLEDGE_STORAGE.md](KNOWLEDGE_STORAGE.md), решение — ADR-011.

Размещение модулей описывает [STRUCTURE.md](STRUCTURE.md), ограничения — [INVARIANTS.md](INVARIANTS.md), основание выбранного направления — [DECISIONS.md](DECISIONS.md).
