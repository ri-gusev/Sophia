# Журнал архитектурных решений

## ADR-024 — Добровольное согласие на рассылки (2026-11-25)

Согласие на рассылки хранится отдельно от трёх обязательных подтверждений. Первая отметка относится к заявке. Согласие связывается с аккаунтом в транзакции активации после отдельной отметки владельца email. Отзыв из профиля фиксирует время в той же записи. Миграция 4 добавляет одну таблицу, связанную с заявкой внешним ключом. [Сценарии и хранение](ACCOUNTS_AND_PROGRESS.md#регистрация-и-восстановление) · [Юридический аудит](../legal/DATA_PROCESSING.md#рекламные-и-информационные-рассылки).

Миграция 5 хранит согласия из профиля по ID аккаунта. Новое согласие после отзыва получает отдельную запись. Действующее согласие определяется по записям регистрации и профиля. Повтор одного запроса сохраняет исходную дату, а удаление аккаунта удаляет обе истории каскадно.

## ADR-023 — Редакции документов, срок заявки и удаление аккаунта (2026-11-25)

Проекты документов доступны через общий футер. Публичное создание и активацию контролирует сервер по утверждённой редакции. Заявка и повторные письма имеют общий срок, а отметки заявителя связываются с аккаунтом и временем повторного подтверждения почты в транзакции. SQLite хранит снимки редакций без данных пользователей отдельно от записей подтверждений. Закрытие аккаунта после проверки текущего пароля удаляет связанные данные каскадно. Прикладной планировщик и CLI выполняют одну и ту же очистку истёкших записей. Порядок удаления из внешних систем и самостоятельные основания для хранения после закрытия требуют подтверждения владельца. [Аудит и эксплуатационные условия](../legal/DATA_PROCESSING.md).

## ADR-022 — Почтовые домены для регистрации (2026-11-25)

Один список проверенных доменов применяется в форме и серверных операциях создания аккаунта. Сервер проверяет новый адрес до хранения и отправки письма и повторно проверяет адрес заявки при активации. Тот же список предусмотрен для нового адреса при реализации смены email. Активированные аккаунты входят и восстанавливаются по текущему адресу. Аудит трансграничных передач продолжается по каждому потоку данных. [Контракт аккаунтов](ACCOUNTS_AND_PROGRESS.md#регистрация-и-восстановление) · [Аудит](../audits/CROSS_BORDER_DATA_TRANSFERS.md).

## ADR-021 — Временное отключение публичного ИИ-чата (2026-11-25)

Решение о доступности принимает сервер при обработке запроса. Точное `AI_CHAT_ENABLED=true` разрешает чат в режиме `CHAT_ACCESS_MODE=local` при локальной работе аккаунтов. Режим `proxy` чата или аккаунтов оставляет публичный чат закрытым. Для закрытого чата POST возвращает 503 до проверки сессии, чтения тела, доступа к журналу квот, RAG и OpenAI. Корневой layout передаёт вычисленную доступность интерфейсу. Окна на `/` и `/learn` и страница `/chat` используют общий компонент. [Контракт и границы](PLATO_CHAT_SECURITY.md).

## ADR-020 — Транспорт писем аккаунтов (2026-11-24)

Для публичного режима выбран серверный EmailService на Nodemailer и Yandex Cloud Postbox по SMTP с обязательным STARTTLS на порту 587 и проверкой сертификата. Предыдущий транспорт использовал HTTP API провайдера. Тесты продолжают использовать файловый транспорт, доступный в локальном режиме. Для эксплуатации нужны подтверждённый домен, серверные SMTP-учётные данные и исходящий доступ к порту 587. [Параметры запуска](../development/ACCOUNT_SERVER.md).

## Sprint 07 — Аккаунты, прогресс и право на чат

Аккаунты и учебные данные хранятся в отдельной SQLite. Выбраны встроенные криптографические примитивы Node.js, чтобы сохранять хеши всех секретных токенов и использовать транзакционный отзыв сессий без дополнительного хранилища. Гость продолжает учиться с прежними данными, перенос возможен из профиля по явному согласию. Право `ai_chat` проверяется на сервере независимо от учёта расходов Sprint 06. [Схема и границы](ACCOUNTS_AND_PROGRESS.md).

## Debug Sprint 06 — Квоты и бюджет публичного чата

Используется отдельная SQLite на постоянном диске VPS. Атомарные транзакции учитывают частоту и активные запросы и резервируют максимальную стоимость хода до OpenAI. Разделены HTTP-слоты и слоты платных операций. Постоянный реестр расходов не содержит переписку. Доверенный HTTPS-прокси передаёт адрес по отдельному заголовку и подтверждает его общим секретом. При сбое хранилища платные обращения блокируются. [Границы решения и расчёт расходов](PLATO_CHAT_SECURITY.md).

## ADR-018 — Полный локальный урок из типизированных сцен

- **Режим разработки, 2026-11-16.** По запросу пользователя хранение ответов в sessionStorage отключено. Ответы и порядок фигур существуют в React-состоянии текущего открытия урока. Перезагрузка открывает слайд из URL с чистым заданием, старые сохранения игнорируются. Это заменяет описанное ранее восстановление ответов вкладки.

- **Игра шестого шага, 2026-11-16.** В задании ordering список заменён фигурами философов. Pointer Events поддерживают мышь и сенсорный ввод. Нажатия и стрелки клавиатуры предоставляют дополнительные способы перестановки. Чистая функция `reorderItem` переставляет существующий массив `answer.order`, проверка правильности и формат сохранения вкладки используются прежние. Ресурсы фигур указаны в опциях задания.

- **Последующее визуальное уточнение 2026-11-15:** по явному запросу пользователя фон под текстом заменён компактной шапкой: иллюстрация полосой слева, заголовок справа, остальное ниже на белом фоне. Высота изображения 104/88 px; кадрирование в данных изображения. Навигация и хранение не меняются. Прокруткой при открытии и смене сцен управляет только урок: шапка сцены ставится на 24 px ниже реальной шапки сайта, h2 получает фокус. Предыдущее визуальное решение с маской теперь историческое.

- **Дата:** 2026-11-15. **Основание:** утверждённый пользователем сценарий из девяти сцен «Кто такой Платон?».
- **Решение:** сохранить маршрут `/learn`, ID `plato-introduction`, карту и семь блоков каталога. `LessonIntroduction` управляет последовательностью, `LessonScene` — общей художественной композицией, `LessonExercise` — двумя видами заданий. `lesson-data.ts` содержит discriminated union story/single-choice/ordering/completion и дословный сценарий; чистые проверки/перестановка/валидация сохранения находятся в `lesson-state.ts`.
- **Навигация и состояние:** URL-фрагмент хранит lesson/scene; валидируемый sessionStorage хранит ответы и проверку только в данной вкладке. Назад сохраняет действия. Отсутствующее/повреждённое хранилище не блокирует урок. После завершения временное состояние очищается, открывается прежний каталог. Учётных записей, сохранения завершённости на сервере, наград и API нет.
- **Задания (уточнение пользователя 2026-11-16):** «Продолжить» доступна после проверки правильного ответа. Ошибочный ответ допускает исправление и повторную проверку. Изменение выбора или порядка сбрасывает проверку текущей попытки. Одинаковое условие применяется к состоянию кнопки и обработчику перехода, правильность вычисляется через `isCorrect`, в том числе для восстановленных ответов. Порядок меняется кнопками с доступными именами. Фокус после проверки переводится на объяснение, после перехода — на заголовок сцены. Закрытие возвращает в каталог.
- **Изображения:** девять локальных оригинальных WebP, происхождение/промпты рядом с ресурсами. Две фоновые image-layer дают плавную смену, текстовая часть проявляется отдельно за ≤1.5 s; reduced motion отключает переходы. Следующее изображение предзагружается по тому же optimized srcset, который использует Next Image. Под текстом нет панели.
- **Источники:** справочники и античное предание сверены; ссылки доступны в закрытом details. Фраза сцены 8 подписана Sophia. Все исторические изображения явно названы художественными интерпретациями. Подробности — [реестр источников](../references/PLATO_LESSON_SOURCES.md).
- **Альтернативы:** девять маршрутов с дублированием UI, новая инфраструктура прогресса и drag-and-drop библиотека не нужны. Уточняет ADR-010/017: вместо одного вступления теперь законченное локальное прохождение.

## ADR-017 — Бесшовный шаблон сцены урока

- **Уточнение по следующему запросу пользователя:** текущий ID урока хранится в URL-фрагменте `#lesson=<id>` через replaceState с сохранением состояния Next.js history. После hydration восстанавливается только ID из собственного каталога INTRO_LESSONS, затем фокус и мгновенная прокрутка к уроку. Перезагрузка больше не скрывает открытый урок. Неизвестный ID игнорируется; radio-ответы, завершённость и прогресс не сохраняются. Новых маршрутов и browser storage нет.

- **Дата:** 2026-11-15. **Основание:** подробное задание пользователя на визуальную переработку существующего урока.
- **Решение:** общий `LessonScene` внутри прежнего блока под картой. Фоновый локальный WebP декоративен, CSS mask-image растворяет его в общий `--page-background`; desktop-переход горизонтальный, mobile вертикальный. Текст и задания без панелей. Типизированные данные содержат изображение и прежнее содержание; локальным выбором по-прежнему управляет `LessonIntroduction`.
- **Расширение:** шаблон принимает sceneId, изображение, заголовок/абзацы, children для задания, navigation и необязательные current/total. Новый sceneId перезапускает анимацию 1.2 s со сдвигом 10 px и задержками 40 ms; reduced motion отключает её. Навигационные кнопки предоставляет вызывающий урок; фиктивное продолжение не добавляется.
- **Границы:** существующее вступление — одна сцена, индикатор показывает позицию, не сохранённый прогресс. Текст/ответы/ID, открытие из каталога и фокус сохранены. Новых маршрутов, API, зависимостей или философского содержания нет. Происхождение и промпт иллюстрации записаны в `public/images/lessons/README.md`.
- **Альтернативы:** отдельная страница, белая карточка или две независимые панели нарушают задание; растягивание карты не соответствует содержанию вступления. Уточняет визуальное решение ADR-010 без изменения его учебной логики.

Здесь фиксируются существенные принятые решения, а не предположения об истории проекта. Начальные записи основаны на явных требованиях пользователя от 2026-10-30. Альтернативы ниже перечислены для пояснения границ выбора; сведений об их прежнем обсуждении нет.

## ADR-016 — Историческая шкала и доступные географические портреты

- **Дата:** 2026-11-13. **Статус:** проект согласован пользователем, реализован.
- **Контекст:** этап 2 требует фильтрации по времени, географически закреплённых портретов 15 философов, обработки совпадающих точек и компактных карточек. Пользователь подтвердил текущий светлый UI и расширение конца шкалы до 270 н. э. для Плотина.
- **Решение:** единственный React-state года в `AtlasView`; отдельные типизированные данные и чистые функции времени/координат/группировки. Исторические даты ненулевые; ось slider непрерывна и включает оба конца жизни. Один город — постоянная биографическая связь, без моделирования путешествий. Неопределённость дат/координат/идентификаций изображений явно отмечена.
- **Маркеры:** существующий Drei Html с DOM-кнопками, проверкой горизонта и Earth-mesh occlusion. Экранная группировка O(n²) для 15 записей не сдвигает географические координаты. Карточка и шкала — отдельный UI. Canvas/текстура/камера стабильны при изменении времени, demand-render и ошибки сохранены.
- **Альтернативы:** sprites потребовали бы отдельной доступной DOM-навигации; новая библиотека кластеризации или картографический движок избыточны. Раздвигание координат нарушает географическую достоверность. Новые зависимости и backend не нужны.
- **Последствия:** портреты хранятся локально с лицензиями; сомнительные идентификации не становятся фактами. Источники/принятые интервалы — [ATLAS_HISTORY](../references/ATLAS_HISTORY.md). Проверки и ограничения — CURRENT_STATE/TESTING.

## ADR-015 — Клиентский 3D-атлас в существующем приложении

- **Дата:** 2026-11-08.
- **Контекст:** отдельный первый этап атласа требует реалистичной Земли с вращением/масштабом. Пользователь указал Three.js/Fiber/Drei, существующий пункт верхней панели и единый UI.
- **Решение:** серверная страница `/atlas`, изолированный feature `philosophy-atlas`, динамическая клиентская сцена без SSR. Three.js 0.187.0, Fiber 9.8.2 и Drei 10.7.9 совместимы с React 19.3.1; типы Three.js — dev-зависимость. Сцена не влияет на `/learn` и чат.
- **Ресурс:** NASA Blue Marble Next Generation, июль 2004, с топографией/батиметрией: локальные JPEG 8192 × 4096 и резерв 4096 × 2048 уменьшены из 21600 × 10800. Атрибуция NASA Earth Observatory и [условия использования](../../public/textures/earth/README.md) сохранены. Runtime не обращается к внешнему поставщику текстур.
- **Визуальное решение:** единый светлый UI Sophia; по уточнению пользователя область сцены прозрачная, без рамки и скруглённого контейнера. Существующий disabled-пункт «Атлас» становится ссылкой; отдельное дублирующее меню не создаётся.
- **Альтернативы:** отдельное приложение/картографический движок нарушили бы заданную интеграцию; Three.js без Fiber/Drei потребовал бы ручного связывания React и жестов и расходился бы с заданным стеком. Полная тёмная тема страницы не сохраняла бы существующий UI.
- **Последствия:** нужны WebGL2 и аппаратное ускорение. Рендер по необходимости, DPR до 2 с резервом 1.5; 8K выбирается по возможностям GPU/подсказке памяти/типу указателя, иначе 4K. Ошибка 8K приводит к 4K, а потеря контекста — к UI с повтором. Есть явное освобождение текстур и штатный cleanup геометрии/материала/управления. При resize сохраняется направление, увеличивается только недостаточная дистанция; явный сброс очищает инерцию. Прежний шейдер с усилением резкости удалён; по последующей обратной связи пользователя `earth-palette.ts` мягко согласует тона суши и океана с UI, сохраняя спутниковую географию и исходные JPEG. Материал матовый, свет направленный с нейтральным заполнением; актуальные параметры — в [дизайн-системе](../design/DESIGN_SYSTEM.md#атлас). На этапе 1 маркеры отсутствовали; исторический слой этапа 2 описан в ADR-016. Нет API, сохранения камеры или новых серверных сервисов.
- **Статус:** согласовано пользователем после описания оформления; реализовано. Проверки и ограничения — [CURRENT_STATE.md](../development/CURRENT_STATE.md).

## ADR-002 — Граница первого этапа

- **ID:** ADR-002.
- **Дата:** 2026-10-30.
- **Контекст:** необходимо показать подход к продукту без преждевременной инфраструктуры.
- **Решение:** первый этап ограничен [MVP](../product/MVP.md); полноценная авторизация, БД, платежи и ИИ-собеседник исключены.
- **Альтернативы:** сразу реализовать полный SaaS; заданием не выбрано.
- **Последствия:** демонстрационные данные хранятся отдельно и типизированно; технологии будущих этапов требуют отдельного решения.
- **Статус:** историческое решение Phase 1; текущий состав страниц уточнён в ADR-004. Запрет преждевременной инфраструктуры сохранён.

## ADR-003 — Локальное демонстрационное взаимодействие

- **ID:** ADR-003.
- **Дата:** 2026-10-30.
- **Контекст:** Phase 1 требует работающего вопроса и выразительных превью без аккаунтов и хранения.
- **Решение:** серверная композиция страницы, локальный React state для упражнения и меню, типизированный учебный контент отдельно; схемы маршрута и атласа остаются статическими. Manrope поставляется локально; Motion ограничен обёрткой появления секций с reduced motion.
- **Альтернативы:** делать всю страницу клиентской, добавлять хранилище или картографический движок; для текущего поведения это избыточно.
- **Последствия:** результат сбрасывается при перезагрузке, страница не обращается к внешним API; будущие учебный движок и прогресс потребуют отдельных задач.
- **Статус:** реализовано в Phase 1; состав демонстраций и размещение вопроса заменены ADR-004. Локальный характер взаимодействия сохранён.

## ADR-004 — Разделение публичной и учебной частей

- **ID:** ADR-004.
- **Дата:** 2026-10-30.
- **Контекст:** пользователь в Phase 2 требует ровно три секции главной и отдельный минимальный `/learn`, сохранив существующий стек и дизайн.
- **Решение:** общий root layout для шрифта/CSS; `(marketing)` и `(learning)` с независимыми layouts. `/` содержит Hero с нейтральным вопросом о корабле Тесея, маршрут и три карточки направлений. `/learn` пока только каркас. Вопрос выделен в feature с отдельными данными; внутренние переходы используют `next/link`.
- **Альтернативы:** оставить одну страницу с якорями или сразу создать образовательный интерфейс; первое не выполняет требование `/learn`, второе выходит за scope.
- **Последствия:** прежние отдельный quiz, атлас-превью, лента, финальный CTA и footer удалены. Атлас/вход обозначены как будущие функции. Компактная учебная шапка содержит логотип и необходимый межстраничный якорь. Идея «Вопроса дня» остаётся отложенной без отдельного блока сейчас.
- **Статус:** реализовано по явному заданию пользователя Phase 2; без БД, авторизации и учебного движка. Ограничение `/learn` каркасом заменено ADR-005; разделение маршрутов и трёхсекционная главная сохранены.

## ADR-005 — Горизонтальная карта курса на `/learn`

- **ID:** ADR-005.
- **Дата:** 2026-10-30.
- **Контекст:** после согласования визуального направления пользователь поручил доработать карту и внедрить её во вторую страницу. Карта должна восприниматься как единый пейзаж; коллажные стыки и крупные заголовки эпох внутри изображения отклонены.
- **Решение:** заменить каркас `/learn` горизонтальной картой пяти эпох по пять шагов. `CourseMap` и локальные стили находятся в `src/features/course-map/`; типизированные эпохи, темы и координаты — в `course-map-data.ts`. Одна локальная панорама `public/images/course-map/course-panorama.webp` служит фоном; SVG-путь и доступные кнопки нанесены поверх. Эпохи выбираются компактной навигацией, карта перемещается перетаскиванием, прокруткой, жестами и клавиатурой. Ознакомление с темой открывает нативный `<dialog>` с явным статусом полного урока.
- **Альтернативы:** коллаж отдельных изображений отклонён пользователем; картографический движок или новая библиотека жестов не требуются для горизонтального локального интерфейса.
- **Последствия:** `/learn` получает работающую навигацию по демонстрационным темам, но учебный движок, завершённость, XP и сохранение прогресса не появляются. Клиентское состояние локально; авторизация, API и БД не добавляются. Сохраняются root layout, учебная шапка, возврат и три секции главной. Настройка reduced motion учитывается при перемещении.
- **Статус:** историческая реализация, проверенная 2026-10-31. Решение об одном фоновом изображении и её масштаб заменены ADR-006 по явному выбору пользователя; локальные взаимодействия, доступность и границы функциональности сохранены. Результаты проверок — в [CURRENT_STATE.md](../development/CURRENT_STATE.md).

Большие заголовки поверх пейзажа не возвращаются. Авторизация, API, БД, зависимости и учебный движок не меняются; просмотр темы не создаёт прогресс. Происхождение и полные сохранённые промпты ресурсов описаны в [README изображений](../../public/images/course-map/README.md).
- **Статус:** принято по явному выбору пользователя; внедрение и актуальные результаты проверок отражаются в [CURRENT_STATE.md](../development/CURRENT_STATE.md). Результаты исторического прогона ADR-005 не подтверждают эту редакцию карты.

## ADR-007 — Единый рисованный ландшафт с видом сверху

- **Дата:** 2026-10-31.
- **Контекст:** пользователь поручил заменить только перспективный пейзаж карты цельным 2D-миром с органичной тропой.
- **Решение:** один локальный WebP 3800 × 650 px вместо пяти сцен и четырёх переходов. Иллюстрация создаётся встроенным image_gen по направляющей существующих координат. Тропа входит в изображение; вторая SVG-дорога, её генератор и CSS-маски удалены. Сцена и узлы сохраняют фиксированную систему координат, поэтому при смене viewport меняется только видимая область.
- **Альтернативы:** смешивание прежних перспективных сцен не исправляет проекцию; отдельные новые сцены требуют повторного ремонта стыков. Новый графический движок не нужен.

Названия, порядок тем, кнопки, управление и диалоги сохранены. Старые изображения доступны в Git-истории; происхождение сохранено в README ресурсов.

## ADR-008 — Детальные расширяемые эпохи и размер одного кадра

- **Дата:** 2026-11-01.
- **Контекст:** пользователь отклонил размытую единую панораму, разрешил небольшой наклон узнаваемых зданий в 2D-иллюстрации, потребовал одну эпоху минимум на видимую область и поля по логотипу. Дополнительно указал на обрезанный дом и будущее расширение карты.
- **Решение:** пять независимых крупных иллюстраций, экспортированных без изменения исходных размеров (1690–1904 × 826–931 px); эпоха отображается как 1180 × 650 px. Четыре отдельно нарисованных перехода с экспортированной прозрачностью краёв образуют непрерывную общую сцену. Общий контейнер совпадает с шапкой; ширина мира вычисляется из ширины и числа эпох. Переходы определяются соседними ID, координаты тропы заданы по ID эпохи. Дом в отмеченном переходе удалён графическим редактированием.
- **Последствия:** новую эпоху можно добавить контентом, изображением, пятью координатами и одним новым переходом; прежние изображения не перерисовываются. Новые эпохи, уроки и функции сейчас не реализуются. Тропа встроена в изображения, кнопки остаются доступными DOM-элементами.
- **Статус:** принято по уточнению пользователя; заменяет ограничения строгой проекции и единого ресурса ADR-007. Учебная архитектура не меняется.

## ADR-009 — Узлы по ID и боковой каталог философа

- **Дата:** 2026-11-01.
- **Контекст:** пользователь задал четыре основных узла Античности и необязательную ветку Платона, сохранив другие эпохи и фон. Уточнение требует отдельной правой половины для каталога, а не наложения на карту.
- **Решение:** типизированная конфигурация main/branch с устойчивыми ID, eraId, позицией, явными иконками и действиями; parentId обязателен для branch. Нумерация используется только в подписях. Конфигурация сопоставляется с отдельными описаниями по ID. Основные древние узлы стоят на существующей нарисованной тропе; отдельный короткий SVG соединяет Платона с веткой меньшего размера.
- **Каталог:** отдельный компонент и данные. Desktop от 1000 px использует две колонки 1:1: карта сужается слева, немодальная панель размещается справа. Mobile использует полноэкранный нативный dialog. Кнопка и Escape закрывают каталог; возвращаются scrollLeft карты, scrollY страницы и фокус. Переключение эпох закрывает каталог перед навигацией. Локальный выбор не является прогрессом.
- **Контент:** исходно три раздела-каркаса; последующим заданием пользователь предоставил семь точных названий тем Платона. Они добавлены в отдельные данные с устойчивыми ID, нумерацией и счётчиком; содержание уроков и перечень произведений пока не добавляются. Секции типизированы как lessons/placeholder. Приложенная схема Miro остаётся референсом связей.
- **Последствия:** перестановка учебных описаний не меняет действия, иконки или координаты узлов; новые узлы требуют явной конфигурации. Фон, другие эпохи, маршруты, зависимости и образовательный движок не меняются.
- **Статус:** принято по заданию и уточнению пользователя.

## ADR-011 — Единая локальная база корпусов

- **Дата:** 2026-11-01.
- **Контекст:** пользователь поручил сохранить предоставленный Markdown без просмотра текста и создать общую базу для файлов всех философов и тем, начиная с Платона. Возможны пересечения между философами. Подключение будущего API-чата в задачу не входит.

Исходные байты сохраняются как BLOB и отдельная копия по SHA-256, без анализа текста. Повторный импорт идемпотентен, обновление создаёт версию. Код и схема в Git, данные полностью игнорируются и не публикуются через приложение.
- **Альтернативы:** PostgreSQL/Prisma потребовали бы установки и настройки ещё не выбранной инфраструктуры; сейчас необходим только локальный импорт источников. Будущее подключение чата и выбор хранения при развёртывании рассматриваются отдельно.

Для резервного копирования и переноса данных нужна отдельная копия всей папки хранилища. Поиск, embeddings, OpenAI API и интерпретация корпуса отсутствуют. Подробности — [KNOWLEDGE_STORAGE.md](KNOWLEDGE_STORAGE.md).
- **Статус:** задача на хранение утверждена пользователем; SQLite выбран в реализации в рамках текущего локального этапа.

## ADR-012 — Чат Платона с памятью только вкладки

- **Дата:** 2026-11-01.
- **Контекст:** пользователь поручил подключить реальный чат с Платоном, выразил опасение о стоимости длинной истории и выбрал сброс беседы после reload вместо хранения между посещениями.
- **Решение:** один Node.js POST `/api/philosopher-chat`, общий корневой React provider для двух страниц, память только в состоянии браузерного документа. Ограниченное окно до 12 сообщений / 16000 символов, резюме до 2000 символов, периодическое сжатие старых пар. Нет серверных сессий и БД переписки. Источники из общей SQLite читаются только на сервере; до четырёх лексически найденных выдержек по 1200 символов.
- **Транспорт и безопасность:** встроенный fetch к OpenAI Responses, `store:false`, серверный ключ, default `gpt-5.4-mini` с reasoning none; ограничены запрос/ответ/время/частота/конкуренция. История и источники не становятся инструкциями. Ошибки не раскрывают тело провайдера. Корпус проверяется до платного сжатия. Параметры и ограничения — [PHILOSOPHER_CHAT.md](PHILOSOPHER_CHAT.md).
- **Последствия:** Node >=24.0.0 теперь нужен самому серверу из-за `node:sqlite`; npm-зависимости не добавлены. Память сжимается с потерями; сохранять всю беседу или помнить предыдущие посещения нельзя. Ограничитель одного процесса не заменяет контроль доступа и расходов при публичном размещении. `store:false` не является обещанием Zero Data Retention со стороны OpenAI.
- **Альтернативы:** полная история в каждом запросе растит расходы; постоянные пользовательские сессии/Redis и облачная история не нужны для выбранного сценария. Память только последних реплик без резюме теряла бы раннюю тему разговора.
- **Статус:** реализовано в рамках задания пользователя; политика памяти выбрана пользователем явно.

## ADR-013 — Исторический диалог и индекс в общей SQLite

- **Дата:** 2026-11-02.
- **Контекст:** пользователь задал historical persona, семантический retrieval, отдельную safety policy и проверку исторических утверждений. ADR-012 сохраняет память только вкладки.
- **Решение:** расширить существующий backend: структура фрагментов/embeddings/FTS5 в той же SQLite (миграция 002), точный cosine scan и RRF вместо отдельной vector-службы. Offline CLI индексирует только изменённые документы через text-embedding-3-small/1536; HTTP переиндексации нет. Structured analysis объединяет semantic safety, query understanding, историческую категорию и bounded state. Генерация и проверка разделены; программная проверка evidence и LLM-проверка всего ответа, максимум одна перегенерация. SSE передаёт только уже проверенный текст; технические источники скрыты в UI.
- **Последствия:** больше API-вызовов/latency, серверный timeout 110 с. Summary остаётся сжатием с потерями; определения дополнительно сохраняются в state. Классификация/валидация вероятностные, без обещания абсолютной достоверности. Порог retrieval требует калибровки; непроверенные метаданные не становятся verified. История/reset остаются локальными операциями, auth/долговременная история не добавлены.
- **Альтернативы:** PostgreSQL/pgvector создали бы новую инфраструктуру при небольшом корпусе. Лексический поиск не удовлетворяет требованию embeddings. Непроверенный streaming несовместим с output validation.
- **Статус:** код, реальная индексация и ограниченные live-проверки выполнены после явного согласия пользователя, снявшего первоначальную автоматическую блокировку. Корпус не содержит подтверждённых metadata, поэтому исторические ответы могут получать abstained; полная достоверность не заявляется. [Детали, конфигурация и ограничения](PLATO_RAG.md).

## ADR-014 — Доверенные правила диалога и отдельная проверка роли

- **Дата:** 2026-11-02.
- **Контекст:** пользователь отметил внешнюю академическую речь, AI-окончания и морализаторство. Per-turn правила внутри блока недоверенных данных могли игнорироваться; claims смешивали философское рассуждение с документированной атрибуцией.
- **Решение:** persona от первого лица, серверные режимы генерации в developer instructions только из закрытых enum/номеров источников. Тексты пользователя/источников/feedback остаются данными. Dynamic schema разрешает factual evidence лишь по verified номерам, semantic validator проверяет весь текст и отдельные dialogue_violations. Одна перегенерация и safety/память сохранены; генерация и проверка используют reasoning low в прежних token limits, анализ none.
- **Проверенные сведения:** две небольшие редакторские заметки по первичным текстам «Апологии Сократа» и «Федона» добавляются к соответствующей теме в orchestration. Они не утверждают личное присутствие/знакомство Платона и не повышают доверие private corpus. Это временная узкая опора для подтверждённых пробелов, не замена общей системы хранения; migrations/embeddings/SQLite/frontend не меняются.
- **Альтернативы:** ослабить факт-проверку или выдать неизвестные сведения за verified — отвергнуто. Перестроить RAG и переиндексировать корпус — выходит за задачу поведения. Полностью фиксировать реплики — мешает живой беседе; ответы генерируются и проходят проверку.
- **Проверка:** полный набор из десяти реальных API-сценариев с дословными ответами, оценка по пяти осям без exact-match; unit-регрессии на стиль и доверенную границу. Вероятностные ошибки и интерпретационные упрощения остаются возможны. [Правила и методика](PLATO_DIALOGUE.md).

- **Уточнение ADR-014 от 2026-11-02:** незнакомое составное название допускает философское исследование его слов и условные эксперименты до определения пользователя. Это не разрешает знания о реальных современных технологиях и не создаёт пользовательское определение в памяти. Для непрозрачных имён сохраняется уточнение; modern_unknown ограничен 1200 символами вместо 220.
## ADR-015 — Статическое расширение Atlas до 2026 года

- **Дата:** 2026-11-13.
- **Решение:** сохранить существующий клиентский атлас; объединить 15 прежних и 65 новых проверенных записей по уникальному ID. Биография отделена от портретного ресурса; отсутствие проверенного изображения или ошибка загрузки отображается инициалами. Публичный реестр содержит авторство, лицензию и оговорки идентификации.
- **Даты и география:** целые исторические годы без нуля, включительные границы; `deathYear:null` для живущих на дату проверки, конец шкалы фиксирован 2026. Приблизительность дат обозначается отдельно. Город — одна явно типизированная биографическая связь, а не положение человека в выбранный год.
- **Навигация:** общий range сохранён; семь условных эпох и точный ввод с выбором эры сокращают путь через 2675 исторических лет. Некорректный черновик не меняет выбранный год. Новых зависимостей и внешнего runtime API нет; освещение, Canvas lifecycle и группировка не переписаны.
- **Последствия:** каталог требует редакторского обновления; исторические разногласия и пределы изображений документируются. Это стартовая подборка, не исчерпывающий канон. Региональное разнообразие дополнено Конфуцием, Тагором, Амбедкаром, Виреду и Дианем.

## ADR-016 — Переиспользуемая сцена диалога (2026-11-17)

В существующий union LessonSceneData добавлен тип dialogue. Контент, реестр персонажей с локальными прозрачными портретами и позиции отделены от DialogueScene. Сцена управляет репликой и завершением в React без API и постоянного хранения; повтор начинает диалог заново. Последняя реплика остаётся видимой, пояснение появляется через 2,4 секунды; уход назад отменяет таймер. Три WebP-слоя используют общий художественный стиль, персонажи выделяются CSS-фильтром. Первый урок не переработан. Остальные слайды второго урока не реализованы; завершение возвращает к каталогу.

## ADR-017 — Сцена наставника (2026-11-17)

Для последовательного объяснения одним персонажем добавлен отдельный вариант mentor-dialogue в существующий union сцен. Тексты, пороги появления схемы и заключение находятся в mentor-data.ts; MentorScene отвечает за представление и локальную навигацию. Сценарий первого диалога не перегружен специальными условиями. LessonIntroduction сохраняет DialogueScene смонтированным под hidden во время переходов внутри текущего урока, чтобы не сбрасывать завершённый разговор; скрытый контент исключён из фокуса, чтения и поиска заголовка для прокрутки. Постоянное хранение состояния не добавлено.

## ADR-018 — Локальное завершение уроков (2026-11-18)

До этой задачи постоянного прогресса уроков не было. Общий lesson-progress.ts сохраняет уникальные lessonId после явного завершения в localStorage (версия ключа v1). Он не является серверной записью или аккаунтом. Ошибки чтения/записи не должны закрывать финал как успешный; каталог отображает только прочитанную локальную запись. Повтор идемпотентен. Первое подключение — финал второго урока, интерфейс первого урока сохранён. Состояние реплик остаётся в рамках текущего прохождения, отдельно от признака завершения.

## ADR-019 — Возобновление всех учебных сцен после reload (2026-11-21)

По требованию пользователя внутреннее состояние слайдов теперь сохраняется в `localStorage` отдельно от признака завершения: `sophia.lesson-resume.v1:<lessonId>`. `lesson-resume.ts` читает версионированный снимок, хранит текущий слайд, обычные упражнения, поля интерактивных сцен и смещение чтения относительно шапки слайда. Относительная координата сохраняет место чтения, даже когда каталог над уроком исчезает после reload.

`useSceneState` оставляет владение состоянием в компоненте и добавляет чтение с проверкой допустимых значений и запись изменений. Все восемь типов интерактивных сцен используют этот hook; ответы первого урока проходят существующий `restoreRun`. Блок «Источники и иллюстрации» хранит раскрытие отдельно для каждого слайда через keyed `LessonSources`. Ссылка на конкретный слайд имеет приоритет над сохранённым номером; открытие из каталога возобновляет сохранённый слайд. Кнопки повтора записывают сброшенные значения. Начальная отрисовка урока происходит после гидратации CourseMap, поэтому браузерное состояние доступно до первого видимого кадра сцены.

Автоматический фокус на заголовки и их `tabIndex` удалены. Прокрутка к новым этапам и управление фокусом на задании/поле ввода сохранены. Автопрокрутки наставника и проверенного ответа не запускаются повторно при восстановлении. Повреждённое или недоступное хранилище не блокирует урок; без доступного хранилища возобновление после reload невозможно. Это локальные данные браузера, без аккаунта и синхронизации; `lesson-progress.ts` и явное завершение не изменены.

В уроке о добродетели кнопка перехода на предыдущий слайд очищает поля и позицию прокрутки покидаемой сцены и пересоздаёт её локальное состояние. Принимающий слайд восстанавливается из сохранённого состояния. Шаг назад внутри слайда сохраняется как новый текущий этап в том же снимке.
## Debug Sprint 02 — Подтверждение слайдов и завершения

Записи `sophia.lesson-progress.v2:slide:<lessonId>:<sceneId>` добавляются после финального действия слайда. У каждой записи собственный ключ, поэтому записи разных слайдов из двух вкладок не перезаписывают друг друга. Завершение урока требует отдельного подтверждения в финале и проверки всех слайдов. Каталог читает прежний `sophia.lesson-completions.v1` как «Завершено ранее» без миграции. Снимки возобновления остаются в `lesson-resume.ts`, переходы по оглавлению их не сбрасывают.

## Debug Sprint 03 — Раздельные записи возобновления

`lesson-resume.v2` хранит текущий слайд урока, ответ обычного упражнения, поля интерактивной сцены и её прокрутку отдельными записями. Для одной записи действует последняя успешная запись. Значения v1 используются как запасные, пока пользователь не сохранит новое значение или не сбросит сцену. Старый снимок сохраняется. При сбросе новая версия сцены скрывает прежние поля и прокрутку, не затрагивая зачёт и остальные слайды.

Перед записью финального зачёта проверяются все предыдущие слайды. Запись финального зачёта и запись завершения остаются двумя операциями. Если вторая операция не удалась, каталог не объявляет урок пройденным, а пользователь может повторить завершение.

## ADR-021 — Московский календарь и локальная серия ежедневного вопроса

Исходная дата цикла — 25 ноября 2026 года. Порядок записей в статическом JSON задаёт последовательность вопросов. Индекс равен номеру московского календарного дня относительно даты начала по модулю 250. Идентификаторы и их позиции сохраняются при редактуре базы, чтобы уже сохранённые ответы продолжали указывать на свои вопросы.

Hero передаёт дату из SSR для первого рендера. После гидратации карточка обновляет дату по часам устройства и `Europe/Moscow`, ставит таймер на ближайшую московскую полночь и повторяет проверку при возвращении к вкладке. Атомарная запись одного локального снимка выполняется внутри Web Lock при его наличии. Второй ответ за те же сутки проверяет уже записанную дату. Вкладки обновляют снимок по событию `storage`. Без Web Locks параллельные ответы за одни сутки дают одинаковое число дней, а при одновременной записи может сохраниться последний из вариантов.
