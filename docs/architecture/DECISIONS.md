# Журнал архитектурных решений

Здесь фиксируются существенные принятые решения, а не предположения об истории проекта. Начальные записи основаны на явных требованиях пользователя от 2026-10-30. Альтернативы ниже перечислены для пояснения границ выбора; сведений об их прежнем обсуждении нет.

## ADR-001 — Единое приложение и утверждённый стек

- **ID:** ADR-001.
- **Дата:** 2026-10-30.
- **Контекст:** требуется зафиксировать основу долгосрочной разработки Sophia до появления исходников.
- **Решение:** ранняя архитектура — модульный монолит Next.js App Router; утверждённый набор технологий перечислен в [TECH_STACK.md](TECH_STACK.md).
- **Альтернативы:** отдельные сервисы или другой стек; заданием не выбраны.
- **Последствия:** последующая реализация следует единому приложению; версии выбираются при инициализации; новые сервисы не создаются заранее.
- **Статус:** принято пользователем в задании; реализовано для Phase 1 от 2026-10-30.

## ADR-002 — Граница первого этапа

- **ID:** ADR-002.
- **Дата:** 2026-10-30.
- **Контекст:** необходимо показать подход к продукту без преждевременной инфраструктуры.
- **Решение:** первый этап ограничен [MVP](../product/MVP.md); полноценная авторизация, БД, платежи и ИИ-собеседник исключены.
- **Альтернативы:** сразу реализовать полный SaaS; заданием не выбрано.
- **Последствия:** демонстрационные данные хранятся отдельно и типизированно; технологии будущих этапов требуют отдельного решения.
- **Статус:** историческое решение Phase 1; текущий состав страниц уточнён в ADR-004. Запрет преждевременной инфраструктуры сохранён.

## ADR-003 — Локальное демонстрационное взаимодействие

- **ID:** ADR-003.
- **Дата:** 2026-10-30.
- **Контекст:** Phase 1 требует работающего вопроса и выразительных превью без аккаунтов и хранения.
- **Решение:** серверная композиция страницы, локальный React state для упражнения и меню, типизированный учебный контент отдельно; схемы маршрута и атласа остаются статическими. Manrope поставляется локально; Motion ограничен обёрткой появления секций с reduced motion.
- **Альтернативы:** делать всю страницу клиентской, добавлять хранилище или картографический движок; для текущего поведения это избыточно.
- **Последствия:** результат сбрасывается при перезагрузке, страница не обращается к внешним API; будущие учебный движок и прогресс потребуют отдельных задач.
- **Статус:** реализовано в Phase 1; состав демонстраций и размещение вопроса заменены ADR-004. Локальный характер взаимодействия сохранён.

## ADR-004 — Разделение публичной и учебной частей

- **ID:** ADR-004.
- **Дата:** 2026-10-30.
- **Контекст:** пользователь в Phase 2 требует ровно три секции главной и отдельный минимальный `/learn`, сохранив существующий стек и дизайн.
- **Решение:** общий root layout для шрифта/CSS; `(marketing)` и `(learning)` с независимыми layouts. `/` содержит Hero с нейтральным вопросом о корабле Тесея, маршрут и три карточки направлений. `/learn` пока только каркас. Вопрос выделен в feature с отдельными данными; внутренние переходы используют `next/link`.
- **Альтернативы:** оставить одну страницу с якорями или сразу создать образовательный интерфейс; первое не выполняет требование `/learn`, второе выходит за scope.
- **Последствия:** прежние отдельный quiz, атлас-превью, лента, финальный CTA и footer удалены. Атлас/вход обозначены как будущие функции. Компактная учебная шапка содержит логотип и необходимый межстраничный якорь. Идея «Вопроса дня» остаётся отложенной без отдельного блока сейчас.
- **Статус:** реализовано по явному заданию пользователя Phase 2; без БД, авторизации и учебного движка.

## Добавление записей

Новая запись содержит ID, дату, контекст, принятое решение, альтернативы, последствия и статус. Используй следующий свободный `ADR-NNN`. Предложение отмечай как предложенное, принятое решение — как принятое. При замене решения сохраняй старую запись со ссылкой на новую и статусом «заменено». Не датируй решения задним числом.
