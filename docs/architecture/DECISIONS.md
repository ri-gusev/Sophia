# Журнал архитектурных решений

Здесь фиксируются существенные принятые решения, а не предположения об истории проекта. Начальные записи основаны на явных требованиях пользователя от 2026-10-30. Альтернативы ниже перечислены для пояснения границ выбора; сведений об их прежнем обсуждении нет.

## ADR-016 — Историческая шкала и доступные географические портреты

- **Дата:** 2026-11-13. **Статус:** проект согласован пользователем, реализован.
- **Контекст:** этап 2 требует фильтрации по времени, географически закреплённых портретов 15 философов, обработки совпадающих точек и компактных карточек. Пользователь подтвердил текущий светлый UI и расширение конца шкалы до 270 н. э. для Плотина.
- **Решение:** единственный React-state года в `AtlasView`; отдельные типизированные данные и чистые функции времени/координат/группировки. Исторические даты ненулевые; ось slider непрерывна и включает оба конца жизни. Один город — постоянная биографическая связь, без моделирования путешествий. Неопределённость дат/координат/идентификаций изображений явно отмечена.
- **Маркеры:** существующий Drei Html с DOM-кнопками, проверкой горизонта и Earth-mesh occlusion. Экранная группировка O(n²) для 15 записей не сдвигает географические координаты. Карточка и шкала — отдельный UI. Canvas/текстура/камера стабильны при изменении времени, demand-render и ошибки сохранены.
- **Альтернативы:** sprites потребовали бы отдельной доступной DOM-навигации; новая библиотека кластеризации или картографический движок избыточны. Раздвигание координат нарушает географическую достоверность. Новые зависимости и backend не нужны.
- **Последствия:** портреты хранятся локально с лицензиями; сомнительные идентификации не становятся фактами. Источники/принятые интервалы — [ATLAS_HISTORY](../references/ATLAS_HISTORY.md). Проверки и ограничения — CURRENT_STATE/TESTING.

## ADR-015 — Клиентский 3D-атлас в существующем приложении

- **Дата:** 2026-11-08.
- **Контекст:** отдельный первый этап атласа требует реалистичной Земли с вращением/масштабом. Пользователь указал Three.js/Fiber/Drei, существующий пункт верхней панели и единый UI.
- **Решение:** серверная страница `/atlas`, изолированный feature `philosophy-atlas`, динамическая клиентская сцена без SSR. Three.js 0.187.0, Fiber 9.8.2 и Drei 10.7.9 совместимы с React 19.3.1; типы Three.js — dev-зависимость. Сцена не влияет на `/learn` и чат.
- **Ресурс:** NASA Blue Marble Next Generation, июль 2004, с топографией/батиметрией: локальные JPEG 8192 × 4096 и резерв 4096 × 2048 уменьшены из 21600 × 10800. Атрибуция NASA Earth Observatory и [условия использования](../../public/textures/earth/README.md) сохранены. Runtime не обращается к внешнему поставщику текстур.
- **Визуальное решение:** единый светлый UI Sophia; по уточнению пользователя область сцены прозрачная, без рамки и скруглённого контейнера. Существующий disabled-пункт «Атлас» становится ссылкой; отдельное дублирующее меню не создаётся.
- **Альтернативы:** отдельное приложение/картографический движок нарушили бы заданную интеграцию; Three.js без Fiber/Drei потребовал бы ручного связывания React и жестов и расходился бы с заданным стеком. Полная тёмная тема страницы не сохраняла бы существующий UI.
- **Последствия:** нужны WebGL2 и аппаратное ускорение. Рендер по необходимости, DPR до 2 с резервом 1.5; 8K выбирается по возможностям GPU/подсказке памяти/типу указателя, иначе 4K. Ошибка 8K приводит к 4K, а потеря контекста — к UI с повтором. Есть явное освобождение текстур и штатный cleanup геометрии/материала/управления. При resize сохраняется направление, увеличивается только недостаточная дистанция; явный сброс очищает инерцию. Прежний шейдер с усилением резкости удалён; по последующей обратной связи пользователя `earth-palette.ts` мягко согласует тона суши и океана с UI, сохраняя спутниковую географию и исходные JPEG. Материал матовый, свет направленный с нейтральным заполнением; актуальные параметры — в [дизайн-системе](../design/DESIGN_SYSTEM.md#атлас). На этапе 1 маркеры отсутствовали; исторический слой этапа 2 описан в ADR-016. Нет API, сохранения камеры или новых серверных сервисов.
- **Статус:** согласовано пользователем после описания оформления; реализовано. Проверки и ограничения — [CURRENT_STATE.md](../development/CURRENT_STATE.md).

## ADR-003 — Локальное демонстрационное взаимодействие

- **ID:** ADR-003.
- **Дата:** 2026-10-30.
- **Контекст:** Phase 1 требует работающего вопроса и выразительных превью без аккаунтов и хранения.
- **Решение:** серверная композиция страницы, локальный React state для упражнения и меню, типизированный учебный контент отдельно; схемы маршрута и атласа остаются статическими. Manrope поставляется локально; Motion ограничен обёрткой появления секций с reduced motion.
- **Альтернативы:** делать всю страницу клиентской, добавлять хранилище или картографический движок; для текущего поведения это избыточно.
- **Последствия:** результат сбрасывается при перезагрузке, страница не обращается к внешним API; будущие учебный движок и прогресс потребуют отдельных задач.
- **Статус:** реализовано в Phase 1; состав демонстраций и размещение вопроса заменены ADR-004. Локальный характер взаимодействия сохранён.

## ADR-004 — Разделение публичной и учебной частей

- **ID:** ADR-004.
- **Дата:** 2026-10-30.
- **Контекст:** пользователь в Phase 2 требует ровно три секции главной и отдельный минимальный `/learn`, сохранив существующий стек и дизайн.
- **Решение:** общий root layout для шрифта/CSS; `(marketing)` и `(learning)` с независимыми layouts. `/` содержит Hero с нейтральным вопросом о корабле Тесея, маршрут и три карточки направлений. `/learn` пока только каркас. Вопрос выделен в feature с отдельными данными; внутренние переходы используют `next/link`.
- **Альтернативы:** оставить одну страницу с якорями или сразу создать образовательный интерфейс; первое не выполняет требование `/learn`, второе выходит за scope.
- **Последствия:** прежние отдельный quiz, атлас-превью, лента, финальный CTA и footer удалены. Атлас/вход обозначены как будущие функции. Компактная учебная шапка содержит логотип и необходимый межстраничный якорь. Идея «Вопроса дня» остаётся отложенной без отдельного блока сейчас.
- **Статус:** реализовано по явному заданию пользователя Phase 2; без БД, авторизации и учебного движка. Ограничение `/learn` каркасом заменено ADR-005; разделение маршрутов и трёхсекционная главная сохранены.

## ADR-005 — Горизонтальная карта курса на `/learn`

- **ID:** ADR-005.
- **Дата:** 2026-10-30.
- **Контекст:** после согласования визуального направления пользователь поручил доработать карту и внедрить её во вторую страницу. Карта должна восприниматься как единый пейзаж; коллажные стыки и крупные заголовки эпох внутри изображения отклонены.
- **Решение:** заменить каркас `/learn` горизонтальной картой пяти эпох по пять шагов. `CourseMap` и локальные стили находятся в `src/features/course-map/`; типизированные эпохи, темы и координаты — в `course-map-data.ts`. Одна локальная панорама `public/images/course-map/course-panorama.webp` служит фоном; SVG-путь и доступные кнопки нанесены поверх. Эпохи выбираются компактной навигацией, карта перемещается перетаскиванием, прокруткой, жестами и клавиатурой. Ознакомление с темой открывает нативный `<dialog>` с явным статусом полного урока.
- **Альтернативы:** коллаж отдельных изображений отклонён пользователем; картографический движок или новая библиотека жестов не требуются для горизонтального локального интерфейса.
- **Последствия:** `/learn` получает работающую навигацию по демонстрационным темам, но учебный движок, завершённость, XP и сохранение прогресса не появляются. Клиентское состояние локально; авторизация, API и БД не добавляются. Сохраняются root layout, учебная шапка, возврат и три секции главной. Настройка reduced motion учитывается при перемещении.
- **Статус:** историческая реализация, проверенная 2026-10-31. Решение об одном фоновом изображении и её масштаб заменены ADR-006 по явному выбору пользователя; локальные взаимодействия, доступность и границы функциональности сохранены. Результаты проверок — в [CURRENT_STATE.md](../development/CURRENT_STATE.md).

## ADR-006 — Восстановление масштаба и сцен согласованного прототипа

- **ID:** ADR-006.
- **Дата:** 2026-10-31.
- **Контекст:** пользователь указал этап прототипа `sophia-learning-map-v4.html` как лучший по масштабу и оформлению и поручил вернуть его на сайт, доработав стыки и объём кнопок. Компактная единая панорама ADR-005 изменила утверждённую композицию слишком сильно. Требование убрать крупные карточки названий эпох остаётся в силе.
- **Решение:** восстановить мир 3800 × 650 px с пятью эпохами шириной 760 px и пятью шагами в каждой. Использовать пять локальных `era-{id}.webp` в `public/images/course-map/` и четыре отдельно отредактированных изображения переходов 760 × 650 px. Каждый переход начинается за 380 px до границы эпох и закрывает её; CSS-маска смягчает внешние края. Один SVG-путь связывает все 25 шагов. Объёмная кнопка собирается из DOM/CSS-слоёв: лицевая поверхность 86 × 73 px, отдельная боковина глубиной 18 px, обод, материал, свет и контактная тень. Материалы эпох: мрамор/бронза, дуб/железо, латунь/медь, орех/эмаль и стекло/сплав. Типизированные данные и геометрия остаются отдельно от UI, управление и нативный диалог сохраняются.
- **Альтернативы:** растянуть компактную панораму ADR-005 — не возвращает выбранную пользователем детализацию и сцены; оставить старые узкие переходы прототипа — сохраняет отклонённые видимые стыки. Новая библиотека рендера, canvas или картографический движок не нужны.
- **Последствия:** увеличивается число локальных фоновых ресурсов, но сохраняются выбранные сцены, крупные шаги и горизонтальное исследование без уменьшения мира на мобильном. Большие заголовки поверх пейзажа не возвращаются. Авторизация, API, БД, зависимости и учебный движок не меняются; просмотр темы не создаёт прогресс. Происхождение и полные сохранённые промпты ресурсов описаны в [README изображений](../../public/images/course-map/README.md).
- **Статус:** принято по явному выбору пользователя; внедрение и актуальные результаты проверок отражаются в [CURRENT_STATE.md](../development/CURRENT_STATE.md). Результаты исторического прогона ADR-005 не подтверждают эту редакцию карты.

## ADR-007 — Единый рисованный ландшафт с видом сверху

- **Дата:** 2026-10-31.
- **Контекст:** пользователь поручил заменить только перспективный пейзаж карты цельным 2D-миром с органичной тропой.
- **Решение:** один локальный WebP 3800 × 650 px вместо пяти сцен и четырёх переходов. Иллюстрация создаётся встроенным image_gen по направляющей существующих координат. Тропа входит в изображение; вторая SVG-дорога, её генератор и CSS-маски удалены. Сцена и узлы сохраняют фиксированную систему координат, поэтому при смене viewport меняется только видимая область.
- **Альтернативы:** смешивание прежних перспективных сцен не исправляет проекцию; отдельные новые сцены требуют повторного ремонта стыков. Новый графический движок не нужен.
- **Последствия:** изменения координат в будущем требуют согласованного редактирования иллюстрации и визуальной проверки тропы; это не динамическая система маршрутизации. Названия, порядок тем, кнопки, управление и диалоги сохранены. Старые изображения доступны в Git-истории; происхождение сохранено в README ресурсов.
- **Статус:** принято по заданию пользователя; заменяет только способ отрисовки ландшафта и дороги ADR-006.

## ADR-008 — Детальные расширяемые эпохи и размер одного кадра

- **Дата:** 2026-11-01.
- **Контекст:** пользователь отклонил размытую единую панораму, разрешил небольшой наклон узнаваемых зданий в 2D-иллюстрации, потребовал одну эпоху минимум на видимую область и поля по логотипу. Дополнительно указал на обрезанный дом и будущее расширение карты.
- **Решение:** пять независимых крупных иллюстраций, экспортированных без изменения исходных размеров (1690–1904 × 826–931 px); эпоха отображается как 1180 × 650 px. Четыре отдельно нарисованных перехода с экспортированной прозрачностью краёв образуют непрерывную общую сцену. Общий контейнер совпадает с шапкой; ширина мира вычисляется из ширины и числа эпох. Переходы определяются соседними ID, координаты тропы заданы по ID эпохи. Дом в отмеченном переходе удалён графическим редактированием.
- **Последствия:** новую эпоху можно добавить контентом, изображением, пятью координатами и одним новым переходом; прежние изображения не перерисовываются. Новые эпохи, уроки и функции сейчас не реализуются. Тропа встроена в изображения, кнопки остаются доступными DOM-элементами.
- **Статус:** принято по уточнению пользователя; заменяет ограничения строгой проекции и единого ресурса ADR-007. Учебная архитектура не меняется.

## ADR-009 — Узлы по ID и боковой каталог философа

- **Дата:** 2026-11-01.
- **Контекст:** пользователь задал четыре основных узла Античности и необязательную ветку Платона, сохранив другие эпохи и фон. Уточнение требует отдельной правой половины для каталога, а не наложения на карту.
- **Решение:** типизированная конфигурация main/branch с устойчивыми ID, eraId, позицией, явными иконками и действиями; parentId обязателен для branch. Нумерация используется только в подписях. Конфигурация сопоставляется с отдельными описаниями по ID. Основные древние узлы стоят на существующей нарисованной тропе; отдельный короткий SVG соединяет Платона с веткой меньшего размера.
- **Каталог:** отдельный компонент и данные. Desktop от 1000 px использует две колонки 1:1: карта сужается слева, немодальная панель размещается справа. Mobile использует полноэкранный нативный dialog. Кнопка и Escape закрывают каталог; возвращаются scrollLeft карты, scrollY страницы и фокус. Переключение эпох закрывает каталог перед навигацией. Локальный выбор не является прогрессом.
- **Контент:** исходно три раздела-каркаса; последующим заданием пользователь предоставил семь точных названий тем Платона. Они добавлены в отдельные данные с устойчивыми ID, нумерацией и счётчиком; содержание уроков и перечень произведений пока не добавляются. Секции типизированы как lessons/placeholder. Приложенная схема Miro остаётся референсом связей.
- **Последствия:** перестановка учебных описаний не меняет действия, иконки или координаты узлов; новые узлы требуют явной конфигурации. Фон, другие эпохи, маршруты, зависимости и образовательный движок не меняются.
- **Статус:** принято по заданию и уточнению пользователя.

## ADR-010 — Первый вводный урок под картой

- **Дата:** 2026-11-01.
- **Контекст:** пользователь поручил по нажатию темы переносить пользователя ниже карты и каталога и реализовать только вступление первого урока с мини-вопросом и тремя вариантами.
- **Решение:** необязательный типизированный contentId у темы связывает её с отдельными статическими данными вступления. CourseMap хранит выбранный ID и показывает блок после workspace, переводит фокус на заголовок и прокручивает страницу с учётом prefers-reduced-motion. На mobile закрывает modal-каталог перед переходом; desktop-каталог остаётся сверху. Порядок темы в массиве не управляет действием.
- **Границы:** реализован только plato-introduction. Шесть остальных тем помечены «Скоро». Вопрос предлагает предположение, не проверяет историческую цитату; выбранный вариант подсвечивается без оценки. Нет следующих экранов, прогресса, хранилища, API или новых маршрутов.
- **Статус:** принято по заданию пользователя.

## ADR-011 — Единая локальная база корпусов

- **Дата:** 2026-11-01.
- **Контекст:** пользователь поручил сохранить предоставленный Markdown без просмотра текста и создать общую базу для файлов всех философов и тем, начиная с Платона. Возможны пересечения между философами. Подключение будущего API-чата в задачу не входит.
- **Решение:** SQLite через встроенный `node:sqlite`, без дополнительной библиотеки или службы. Одна база `storage/knowledge/sophia-knowledge.sqlite`; таблицы философов, тем, документов, версий и связей многие-ко-многим. Исходные байты сохраняются как BLOB и отдельная копия по SHA-256, без анализа текста. Повторный импорт идемпотентен, обновление создаёт версию. Код и схема в Git, данные полностью игнорируются и не публикуются через приложение.
- **Альтернативы:** PostgreSQL/Prisma потребовали бы установки и настройки ещё не выбранной инфраструктуры; сейчас необходим только локальный импорт источников. Будущее подключение чата и выбор хранения при развёртывании рассматриваются отдельно.
- **Последствия:** служебные TypeScript-команды требуют Node.js 24, минимальное окружение Next.js-интерфейса не меняется. Для резервного копирования и переноса данных нужна отдельная копия всей папки хранилища. Поиск, embeddings, OpenAI API и интерпретация корпуса отсутствуют. Подробности — [KNOWLEDGE_STORAGE.md](KNOWLEDGE_STORAGE.md).
- **Статус:** задача на хранение утверждена пользователем; SQLite выбран в реализации в рамках текущего локального этапа.

## ADR-012 — Чат Платона с памятью только вкладки

- **Дата:** 2026-11-01.
- **Контекст:** пользователь поручил подключить реальный чат с Платоном, выразил опасение о стоимости длинной истории и выбрал сброс беседы после reload вместо хранения между посещениями.
- **Решение:** один Node.js POST `/api/philosopher-chat`, общий корневой React provider для двух страниц, память только в состоянии браузерного документа. Ограниченное окно до 12 сообщений / 16000 символов, резюме до 2000 символов, периодическое сжатие старых пар. Нет серверных сессий и БД переписки. Источники из общей SQLite читаются только на сервере; до четырёх лексически найденных выдержек по 1200 символов.
- **Транспорт и безопасность:** встроенный fetch к OpenAI Responses, `store:false`, серверный ключ, default `gpt-5.4-mini` с reasoning none; ограничены запрос/ответ/время/частота/конкуренция. История и источники не становятся инструкциями. Ошибки не раскрывают тело провайдера. Корпус проверяется до платного сжатия. Параметры и ограничения — [PHILOSOPHER_CHAT.md](PHILOSOPHER_CHAT.md).
- **Последствия:** Node >=24.0.0 теперь нужен самому серверу из-за `node:sqlite`; npm-зависимости не добавлены. Память сжимается с потерями; сохранять всю беседу или помнить предыдущие посещения нельзя. Ограничитель одного процесса не заменяет контроль доступа и расходов при публичном размещении. `store:false` не является обещанием Zero Data Retention со стороны OpenAI.
- **Альтернативы:** полная история в каждом запросе растит расходы; постоянные пользовательские сессии/Redis и облачная история не нужны для выбранного сценария. Память только последних реплик без резюме теряла бы раннюю тему разговора.
- **Статус:** реализовано в рамках задания пользователя; политика памяти выбрана пользователем явно.

## ADR-013 — Исторический диалог и индекс в общей SQLite

- **Дата:** 2026-11-02.
- **Контекст:** пользователь задал historical persona, семантический retrieval, отдельную safety policy и проверку исторических утверждений. ADR-012 сохраняет память только вкладки.
- **Решение:** расширить существующий backend: структура фрагментов/embeddings/FTS5 в той же SQLite (миграция 002), точный cosine scan и RRF вместо отдельной vector-службы. Offline CLI индексирует только изменённые документы через text-embedding-3-small/1536; HTTP переиндексации нет. Structured analysis объединяет semantic safety, query understanding, историческую категорию и bounded state. Генерация и проверка разделены; программная проверка evidence и LLM-проверка всего ответа, максимум одна перегенерация. SSE передаёт только уже проверенный текст; технические источники скрыты в UI.
- **Последствия:** больше API-вызовов/latency, серверный timeout 110 с. Summary остаётся сжатием с потерями; определения дополнительно сохраняются в state. Классификация/валидация вероятностные, без обещания абсолютной достоверности. Порог retrieval требует калибровки; непроверенные метаданные не становятся verified. История/reset остаются локальными операциями, auth/долговременная история не добавлены.
- **Альтернативы:** PostgreSQL/pgvector создали бы новую инфраструктуру при небольшом корпусе. Лексический поиск не удовлетворяет требованию embeddings. Непроверенный streaming несовместим с output validation.
- **Статус:** код, реальная индексация и ограниченные live-проверки выполнены после явного согласия пользователя, снявшего первоначальную автоматическую блокировку. Корпус не содержит подтверждённых metadata, поэтому исторические ответы могут получать abstained; полная достоверность не заявляется. [Детали, конфигурация и ограничения](PLATO_RAG.md).

## ADR-014 — Доверенные правила диалога и отдельная проверка роли

- **Дата:** 2026-11-02.
- **Контекст:** пользователь отметил внешнюю академическую речь, AI-окончания и морализаторство. Per-turn правила внутри блока недоверенных данных могли игнорироваться; claims смешивали философское рассуждение с документированной атрибуцией.
- **Решение:** persona от первого лица, серверные режимы генерации в developer instructions только из закрытых enum/номеров источников. Тексты пользователя/источников/feedback остаются данными. Dynamic schema разрешает factual evidence лишь по verified номерам, semantic validator проверяет весь текст и отдельные dialogue_violations. Одна перегенерация и safety/память сохранены; генерация и проверка используют reasoning low в прежних token limits, анализ none.
- **Проверенные сведения:** две небольшие редакторские заметки по первичным текстам «Апологии Сократа» и «Федона» добавляются к соответствующей теме в orchestration. Они не утверждают личное присутствие/знакомство Платона и не повышают доверие private corpus. Это временная узкая опора для подтверждённых пробелов, не замена общей системы хранения; migrations/embeddings/SQLite/frontend не меняются.
- **Альтернативы:** ослабить факт-проверку или выдать неизвестные сведения за verified — отвергнуто. Перестроить RAG и переиндексировать корпус — выходит за задачу поведения. Полностью фиксировать реплики — мешает живой беседе; ответы генерируются и проходят проверку.
- **Проверка:** полный набор из десяти реальных API-сценариев с дословными ответами, оценка по пяти осям без exact-match; unit-регрессии на стиль и доверенную границу. Вероятностные ошибки и интерпретационные упрощения остаются возможны. [Правила и методика](PLATO_DIALOGUE.md).

- **Уточнение ADR-014 от 2026-11-02:** незнакомое составное название допускает философское исследование его слов и условные эксперименты до определения пользователя. Это не разрешает знания о реальных современных технологиях и не создаёт пользовательское определение в памяти. Для непрозрачных имён сохраняется уточнение; modern_unknown ограничен 1200 символами вместо 220.
