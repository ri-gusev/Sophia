# Запуск аккаунтов Sophia

## Публичный VPS

Перед открытием регистрации утвердите редакции документов и закройте условия из [аудита персональных данных](../legal/DATA_PROCESSING.md). До этого публичный сервер показывает проекты документов и отклоняет создание и активацию аккаунтов. Используйте [production-конфигурацию и приёмку Ubuntu](../../deploy/UBUNTU_PRODUCTION.md).

Используйте один экземпляр Next.js на актуальном Node.js 24 LTS с постоянным локальным диском. Закройте прямой доступ к порту Node.js и принимайте трафик через HTTPS-прокси. Для аккаунтов выберите отдельный SQLite-файл, расположенный вне публичной директории, например `/var/lib/sophia/accounts/accounts.sqlite`. Каталог принадлежит сервисному пользователю с правами 0700, файл имеет права 0600.

| Переменная | Публичное значение |
| --- | --- |
| `ACCOUNT_MODE` | `proxy` |
| `ACCOUNT_ORIGIN` | Точный HTTPS-origin Sophia без завершающего слеша |
| `ACCOUNT_DB_PATH` | Абсолютный путь к постоянной базе аккаунтов |
| `ACCOUNT_REGISTRATION_ENABLED` | `false` до отдельного допуска и вступления в силу выпущенных документов |
| `LEGAL_RELEASE_APPROVED` | `false` до подтверждения оператором версии 1.0 и условий выпуска |
| `LEGAL_RELEASE_EFFECTIVE_DATE` | Дата в формате `YYYY-MM-DD`, назначаемая оператором при выпуске |
| `ACCOUNT_MAIL_TRANSPORT` | `smtp` |
| `SMTP_HOST` | `postbox.cloud.yandex.net` |
| `SMTP_PORT` | `587` |
| `SMTP_FROM` | `noreply@sophialearn.ru` |
| `SMTP_USER` | Идентификатор статического ключа доступа сервисного аккаунта |
| `SMTP_PASSWORD` | SMTP-пароль, вычисленный из секретной части статического ключа |
| `CHAT_PROXY_SECRET` | Общий с HTTPS-прокси секрет из 64 шестнадцатеричных символов |

Сервисный аккаунт должен быть в том же каталоге Yandex Cloud, что и адрес Postbox, и иметь роль `postbox.sender`. Преобразуйте секретную часть статического ключа локально по инструкции Yandex Cloud, в разделе SMTP → «Статический ключ доступа». Передайте приложению полученный SMTP-пароль через серверное окружение. Переменные SMTP хранятся вне Git и без префикса `NEXT_PUBLIC_`. Серверу нужен исходящий доступ к порту 587. Nodemailer требует STARTTLS с TLS 1.2 или выше и проверяет сертификат сервера. [Инструкция Yandex Cloud](https://yandex.cloud/ru/docs/postbox/operations/send-email).

Примените миграции перед запуском от имени сервисного пользователя. В production после миграции нужны `init-deletions` и отдельный абсолютный `ACCOUNT_DELETION_REGISTRY_PATH`. Локальные синтетические прогоны без заданного пути используют частный файл рядом с тестовой базой. [Команды и приёмка](../../deploy/DATA_LIFECYCLE.md#развёртывание-реестра-удалений)

```bash
npm run accounts:migrate
npm run build
npm run start
```

Если переменные хранятся в локальном файле, CLI можно запустить командой `node --env-file=.env.local scripts/accounts/cli.ts migrate`. Перед обновлением, меняющим схему, сохраните резервную копию базы. Миграции повторяемы и приложение также проверяет версию при открытии файла.

Проверьте cookie `__Host-sophia-session` через публичный HTTPS. В обычном браузере должна появляться cookie с `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/` без `Domain`. Проверьте вход и выход, две вкладки, переход из письма и отказ запросов с чужим Origin.

### Проверка доставки после подтверждения DKIM

1. Убедитесь, что у домена в консоли Postbox статус проверки DKIM `Success`. Запустите или перезапустите Sophia с публичными настройками из таблицы на HTTPS-адресе из `ACCOUNT_ORIGIN`. [Проверка домена в Postbox](https://yandex.cloud/ru/docs/postbox/quickstart).
2. На закрытом стенде с согласованными выпускными текстами и синтетическими данными зарегистрируйте новый подконтрольный адрес. Проверьте получение письма от `noreply@sophialearn.ru`. Если проверяете повторную отправку, нажмите «Отправить повторно» до активации и используйте ссылку из последнего письма. Установите пароль по ссылке и войдите.
3. На `/forgot-password` запросите письмо на тот же адрес. Откройте полученную ссылку, измените пароль и проверьте вход с новым паролем.
4. Регистрация, восстановление и повторная отправка подтверждают принятие запроса без ожидания доставки. Сбой доставки учитывается служебным сообщением без адреса и ссылки. Для подтверждения проверяйте фактическое получение писем. При отсутствии письма проверьте конфигурацию SMTP, роль отправителя, статус DKIM и исходящую доступность порта 587.

### Резервная копия

Используйте отдельный [регламент копирования, карантинного восстановления и удаления](../../deploy/DATA_LIFECYCLE.md).

### Очистка истёкших записей

В режиме `proxy` приложение проверяет срок очистки при запуске и использует сохранённую отметку, чтобы повторять очистку каждые 24 часа работы сервера. Для обслуживания остановленного приложения или принудительного запуска используйте то же окружение аккаунтов.

```bash
npm run accounts:cleanup
```

Ротация инфраструктурных логов, снимков и почтовых обращений настраивается у соответствующих поставщиков.

### Тестовый чат

После подтверждения аккаунта владелец сервера может выдать или отозвать право. CLI должен работать с тем же путём к базе, что и приложение.

```bash
npm run accounts:grant-chat -- test-user@example.com
npm run accounts:revoke-chat -- test-user@example.com
```

Чтобы увидеть обновлённое состояние интерфейса, обновите вкладку. Сервер проверяет отзыв на каждом запросе. Использование OpenAI требует отдельной настройки корпуса, ключа и бюджета по [руководству чата](CHAT_SERVER.md).

## Локальная проверка

### SMTP Postbox

Из корня проекта на Node.js 24 выполните проверку подключения, обязательного STARTTLS, сертификата и аутентификации. Укажите свой адрес во второй команде, чтобы отправить тестовое письмо через тот же EmailService, который используют аккаунты.

```powershell
node --env-file=.env.local scripts/accounts/smtp-check.ts --verify
node --env-file=.env.local scripts/accounts/smtp-check.ts --to user@example.com
```

Успешная отправка означает, что Postbox принял письмо в очередь. Проверьте «Входящие» и «Спам» в указанном ящике. Скрипт выводит безопасные коды ошибок SMTP. [Расшифровка кодов Postbox](https://yandex.cloud/ru/docs/postbox/api-ref/smtp-errors).

Для локальной проверки через HTTPS-прокси запустите отдельный экземпляр Sophia на loopback с сертификатом, которому доверяет браузер. Передайте только этому экземпляру `ACCOUNT_MODE=proxy`, точный HTTPS-адрес прокси в `ACCOUNT_ORIGIN`, `ACCOUNT_MAIL_TRANSPORT=smtp` и абсолютный путь к временной базе в `ACCOUNT_DB_PATH`. Перед стартом инициализируйте базу с тем же окружением. Используйте отдельный случайный `CHAT_PROXY_SECRET`, переданный экземпляру и прокси. Прокси должен перезаписывать доверенные заголовки по примеру выше и передавать запросы на loopback-порт Sophia. В этом режиме регистрация требует утверждённых редакций. До утверждения отдельно проверяйте SMTP командой выше и регистрацию на файловом транспорте ниже.

### Файловый транспорт

Выберите приватный каталог с правами 0700 рядом с отдельной тестовой БД. Для пути внутри рабочего дерева допустимы `artifacts/` и `storage/accounts/`. Файл outbox должен быть обычным файлом режима 0600. На Windows ограничьте доступ к каталогу средствами ACL. Обе настройки выполняются только на изолированном локальном стенде.

Укажите `ACCOUNT_MODE=local`, loopback-origin, абсолютные пути к отдельной тестовой базе и файлу исходящих сообщений, затем `ACCOUNT_MAIL_TRANSPORT=test`. Родительский каталог базы создаётся при миграции или запуске локального сценария. Тестовый транспорт пишет ссылку в JSONL локально. Храните файл вне публичных каталогов. Автоматический Playwright запускает собственный loopback-сервер с отдельной временной базой и тестовым исходящим файлом в `artifacts/playwright-accounts/`.

Для локальной копии в `D:/Sophia` добавьте в существующий `.env.local` следующие настройки и откройте приложение по `http://127.0.0.1:3000`. Без настроенного транспорта запрос регистрации возвращает `503`.

```dotenv
ACCOUNT_MODE=local
ACCOUNT_ORIGIN=http://127.0.0.1:3000
ACCOUNT_DB_PATH=D:/Sophia/storage/accounts/accounts.sqlite
ACCOUNT_MAIL_TRANSPORT=test
ACCOUNT_TEST_OUTBOX=D:/Sophia/storage/accounts/dev-outbox.jsonl
```

Для новой регистрации используйте адрес из разрешённого списка, например `test-user@mail.ru`. При файловом транспорте письмо пишется только в тестовый исходящий файл. Скопируйте ссылку из его последней записи и откройте её в том же браузере.

```powershell
(Get-Content -LiteralPath storage/accounts/dev-outbox.jsonl -Tail 1 | ConvertFrom-Json).url
```
