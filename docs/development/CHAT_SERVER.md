# Запуск сервера чата Платона

Для публичного MVP оставьте `AI_CHAT_ENABLED=false`. Отсутствующее или некорректное значение также закрывает чат. POST отвечает 503 без обращения к модели. После смены переменных перезапустите сервер.

## Локально

Начиная со Sprint 07 для отправки запроса нужна активная сессия подтверждённого аккаунта с выданным владельцем правом `ai_chat`. [Настройка аккаунтов и CLI](ACCOUNT_SERVER.md).

Скопируйте [.env.example](../../.env.example) в `.env.local` или перенесите в существующий файл новые переменные. На экземпляре, доступном только через loopback, задайте `AI_CHAT_ENABLED=true`, `ACCOUNT_MODE=local`, `CHAT_ACCESS_MODE=local` и точный loopback-origin с портом, например `CHAT_ALLOWED_ORIGINS=http://127.0.0.1:3000`. Для реальных ответов задайте серверный `OPENAI_API_KEY`. Для live-проверки на 3102 включите этот origin в список. Режим local использует одну общую квоту. `npm.cmd run build` и `npm.cmd run start` запускают production-сборку на loopback. Состояние корпуса проверяет `npm.cmd run knowledge:index-status`.

Платные диагностические сценарии `chat:check:live -- core` и `scripts/chat/persona-eval.ts` последовательно отправляют 9 и 10 вопросов. Задайте `SOPHIA_CHECK_COOKIE` в окружении диагностического запуска как полную пару `sophia-session=…` активной локальной сессии с доступом к чату. Используйте только loopback и храните значение как секрет. Для одного прогона на отдельном loopback-сервере можно задать `CHAT_CLIENT_PER_MINUTE=12` и `CHAT_CLIENT_BURST=12` при глобальном лимите 20. Сначала проверьте остаток бюджета и используемые ключ и базу. Стандартные квоты чата могут ограничить серию быстрых ответов, а 429 в таком прогоне означает ограничение частоты.

## Сохранённая конфигурация для будущего публичного включения

На период MVP режим `proxy` оставляет чат закрытым даже при `AI_CHAT_ENABLED=true`.

Поддерживается один VPS с постоянным локальным диском. Next.js слушает 127.0.0.1. Откройте извне только HTTPS-прокси, закрыв порт Next.js межсетевым экраном и правилами сети. При нескольких независимых серверах до запуска потребуется единое хранилище с атомарными операциями для всех лимитов и резервов. Для production используйте обновлённый Node.js 24 LTS с SQLite, содержащей исправление WAL-reset. Проверено на Node.js 24.22.1 с SQLite 3.53.4. [Примечания SQLite](https://sqlite.org/wal.html#the_wal_reset_bug).

| Переменная | Значение |
| --- | --- |
| `OPENAI_API_KEY` | Ключ выделенного проекта OpenAI. |
| `OPENAI_MODEL` | По умолчанию `gpt-5.4-mini-2026-03-17`. Поддерживается также алиас `gpt-5.4-mini`. |
| `OPENAI_EMBEDDING_MODEL` | `text-embedding-3-small` или `text-embedding-3-large`. Должен совпасть с индексом. |
| `CHAT_ACCESS_MODE` | `proxy` для публичного сервера. |
| `CHAT_ALLOWED_ORIGINS` | Точные HTTPS origin через запятую, без финального слеша. |
| `CHAT_PROXY_SECRET` | Случайные 32 байта как 64 шестнадцатеричных символа. Например, сгенерируйте через `openssl rand -hex 32`. |
| `CHAT_LEDGER_PATH` | Абсолютный путь к предварительно созданному файлу SQLite вне публичной директории. |
| `CHAT_MAX_TURN_USD` | Лимит одного хода. $1.85 покрывает максимальный резерв текущей полной конфигурации. |
| `CHAT_DAY_BUDGET_USD`, `CHAT_MONTH_BUDGET_USD` | Дневной и месячный бюджет в USD. Укажите собственные значения с точкой, например `5` и `20`. Дневной бюджет как минимум равен лимиту хода, месячный как минимум равен дневному. |
| `CHAT_CLIENT_PER_MINUTE`, `CHAT_CLIENT_PER_DAY` | По умолчанию 5 и 40. |
| `CHAT_CLIENT_BURST`, `CHAT_CLIENT_CONCURRENT` | По умолчанию максимум 2 за 5 секунд и 1 одновременно. |
| `CHAT_GLOBAL_PER_MINUTE`, `CHAT_GLOBAL_CONCURRENT`, `CHAT_PAID_CONCURRENT` | По умолчанию 20, 2 и 2. Индивидуальные минутный и одновременный лимиты должны быть строго ниже соответствующих глобальных. |

Выдайте каталогу SQLite права 0700, при первой установке создайте файл с правами 0600 от имени сервисного пользователя. Процесс создаст схему и файлы WAL. Храните базу на постоянном диске, сохраняйте её через SQLite online backup и переносите при обновлении сервера. При недоступности файла, блокировке записи или ошибке БД чат прекращает новые платные обращения. Если сервер перезапустился с незавершёнными резервациями, они остаются в SQLite. Перед восстановлением из старого бэкапа учитывайте расходы после его создания, чтобы откат не увеличил остаток бюджета.

### Пример Nginx на том же VPS

В существующем HTTPS `server` разместите отдельный маршрут для чата. Файл в директиве `include` должен содержать одну директиву `proxy_set_header X-Sophia-Proxy-Token "значение секрета";`. Доступ к нему ограничен пользователем Nginx и администратором. Опция `proxy_request_buffering off` позволяет приложению отклонить запрос до разбора тела. Настройте на внешнем прокси лимиты соединений и тайм-ауты заголовков по доступным ресурсам VPS.

```nginx
location = /api/philosopher-chat {
    client_max_body_size 96k;
    client_body_timeout 5s;
    proxy_http_version 1.1;
    proxy_request_buffering off;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 115s;
    proxy_set_header Host $host;
    proxy_set_header X-Sophia-Client-IP $remote_addr;
    include /etc/nginx/private/sophia-chat-token.conf;
    proxy_pass http://127.0.0.1:3000;
}
```

Этот пример предполагает, что Nginx принимает соединение браузера напрямую. Если перед ним CDN или балансировщик, настройте получение реального адреса только от известных сетей этого поставщика и исключите доступ к origin в обход CDN. Проверьте, что посетитель не может подменить адрес в доверенном заголовке и что отдельный лимит срабатывает в разных вкладках. Адрес CDN вместо клиентского объединит посетителей в одну квоту. Следите, чтобы прокси заменял оба заголовка и исключал токен и тела запросов из логов.

## Мониторинг без переписки

Собирайте `plato_cost` по суммам `spentNanoUsd` и `reservedNanoUsd`. Поле `estimatedOperations` показывает число операций, за которые списана верхняя оценка. Поле `uncertain` означает, что вызов мог продолжить работу после завершения локального запроса. Сигналы `plato_ledger_unavailable` и `plato_cost_envelope_exceeded` требуют проверки хранилища или тарифов. Для оперативного остатка считайте закрытые записи `chat_spend.spent` с `booked` в текущих UTC-сутках или месяце и добавляйте резервы незакрытых ходов. Незакрытый истёкший резерв учитывайте как полный расход с датой `active_until`. Он будет приведён к закрытой записи при следующем успешном резервировании. Экспортируйте только суммы и количества. Раздельный OpenAI-проект упрощает сверку журнала с usage dashboard. Ключ, тексты, поисковые запросы и псевдонимы не нужны для метрик расходов.

## Проверка перед публичным запуском

- [ ] Закрыть прямой доступ к Node.js, подтвердить настройку доверенного HTTPS-прокси и фактический Origin.
- [ ] Проверить снаружи корректный IP, одинаковую квоту вкладок и отказ при подмене proxy-заголовков.
- [ ] Проверить 413, медленное тело, 429 и SSE сквозь production-прокси.
- [ ] Проверить права, постоянный диск и восстановление SQLite. Смоделировать ошибку записи и перезапуск с открытой резервацией на тестовом журнале.
- [ ] Проверить индекс корпуса, модель, актуальные тарифы, бюджеты и оповещения. Убедиться, что chat endpoint закрывается при недостаточном резерве.
- [ ] Сверить браузерное уведомление и правила обработки данных проекта OpenAI. Проверить отсутствие кэша, секретов и сообщений в логах.
