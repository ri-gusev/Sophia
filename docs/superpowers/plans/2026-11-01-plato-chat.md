# Чат Платона с ограниченной памятью

Пользователь разрешил реализовать чат и выбрал память только открытой вкладки: reload начинает новый разговор. Одна API-интеграция и общая база источников сохранены. Корпус не просматривать и не выводить в инструменты; код сервера может искать в нём выдержки для ответа.

## Решение

Один POST `/api/philosopher-chat`, только `plato`. Node.js 24 для доступа к существующей SQLite через `node:sqlite`. Глобальный fetch к Responses API, без SDK и новых зависимостей. Серверные `OPENAI_API_KEY`, `OPENAI_MODEL` (по умолчанию `gpt-5.4-mini`, reasoning none), `store:false`, ограниченные размеры/ответ/время/число запросов и конкуренция. HTTP/API-ошибки не раскрывают тело провайдера, ключ или пользовательский текст.

Память в корневом React provider, чтобы закрытие окна и переходы между `/` и `/learn` сохраняли разговор в одной вкладке. В запросе до 12 недавних сообщений, суммарно до 16000 символов, резюме до 2000 символов. При достижении лимита старые пары сообщений сворачиваются отдельным коротким запросом; остаются последние две пары. Новая память применяется только после успешного ответа. Отображаемая переписка также ограничена. Нет БД истории, cookies, localStorage/sessionStorage или серверных сессий.

Контекст знаний: только последние версии документов, связанных с `plato`, read-only. Локальное лексическое ранжирование небольших фрагментов; до четырёх выдержек по 1200 символов. Отсутствие совпадений не выдаётся за подтверждение источником. Данные истории/резюме/корпуса не становятся инструкциями модели. Цитаты не придумывать, UI обозначает учебного ИИ-собеседника. Семантический поиск и embeddings пока не добавлять.

## Шаги

- [x] Синтетические unit-тесты в `scripts/chat/`: валидация, компактная память без потери последних пар, ограничения контекста, отдельные истории, ошибки/отмена и отказ для других философов; поиск без чтения реального корпуса тестами.
- [x] `chat-contract.ts`, серверные модули provider/retrieval/service/http, тонкий route handler. Протестировать отсутствие `store:true`, произвольных system-ролей и утечки ошибок.
- [x] React provider и отправка в существующем окне: история, загрузка, отмена, ошибка с сохранением вопроса, новый разговор, локальное продолжение после перехода между страницами. Обновить старые UI-проверки и добавить браузерные ответы через явный mock маршрута.
- [x] Проверить реальные серверные валидационные ответы; live-прогон без вывода ключа и корпуса: ответ 200, сжатие длинной беседы и сохранённое имя учебного героя. Проверен источник в ответе.
- [x] TypeScript, ESLint, production build, тесты хранения/чата, весь Playwright; просмотреть mobile/desktop, независимое ревью и обновить CURRENT_STATE/архитектуру/README.

Границы: нет авторизации, новых философов, долговременной памяти, Redis и отдельной инфраструктуры. Ограничитель одного процесса не является распределённой защитой и не заменяет управление доступом при публичном запуске. Не выполнять коммит.
